A dependency-free Python package and CLI that builds a delivered LNG cost from annuitised liquefaction capex, grossed-up feed gas, a round-trip voyage and a levelised regas charge, with an optional bottom-up capex build from steel, cement, labour and equipment and a +/-20% sensitivity. This post installs it, runs the tests and walks through the outputs.

Why it is useful

  • Energy analysts, students and project developers get a transparent cost stack (feed gas, liquefaction capital and O&M, shipping, regas) in one command, instead of a locked spreadsheet.
  • It replaces the first hour of building a screening model: capital-recovery factor, fuel-and-loss gross-up, round-trip voyage with boil-off and port days, and a regas levelised charge are already wired together and unit-tested.
  • The bottom-up mode shows which capex drivers matter: with the defaults, a 20% move in the equipment index shifts delivered cost by 0.45 USD/MMBtu, labour by 0.30, steel by 0.05 and cement by 0.001.
  • Evidence from the run: pip install -e .[dev] and pytest passed 13 tests in 0.08 s; the CLI, the JSON output and the Python API all ran. Every number below comes from illustrative placeholder defaults, not sourced benchmarks, as the README states.

What it is for

lng-cost estimates a delivered LNG cost in USD/MMBtu as the sum of three blocks: liquefaction (capex x CRF / annual MMBtu + fixed O&M + feed gas / (1 - fuel and loss) + other variable), shipping ((days x charter + sea days x burn x bunker + canal) / delivered MMBtu) and regas (capex x (CRF + fixed O&M%) / annual MMBtu + variable). It assumes 52 MMBtu per tonne and 0.45 t per cubic metre, constant real USD, no tax, royalty, inflation or financing during construction.

The bottom-up option builds liquefaction (and regas) capex from quantities of steel, cement, other concrete inputs, labour hours and equipment, scaled from a 5 Mtpa reference with exponent 0.65, with stacked indirects, owner's costs and contingency, and regional multipliers for reference, us_gulf, middle_east, australia and east_africa.

This is a conceptual, screening-level (roughly AACE Class 5) cost estimate, not an engineering design or a bankable cost. All defaults, quantities, prices and regions are placeholders to be replaced with project or quote data.

Who it is for

  • Energy and gas-market analysts who want a quick, auditable delivered-cost stack to compare supply routes
  • Students and researchers learning how LNG value-chain economics are assembled
  • Developers who want a small, typed Python model to calibrate against their own licensed benchmarks
Not for.
  • Engineering design, FEED or investment decisions: this is a conceptual cost estimate, not engineering design, and not investment advice
  • Quoting the default numbers as industry benchmarks: they are illustrative placeholders
  • Fleet, terminal-tank, jetty, pipeline or upstream costs, or uncertainty analysis: none are modelled

Quick start: commands and what you should see

Delivered cost with the defaults

lng-cost

An eight-line cost stack ending in DELIVERED cost 8.49 USD/MMBtu, a 27.5-day round trip with 1.23% boil-off, and the reminder that defaults are placeholders.

Override distance and capex (the README example)

lng-cost --distance-nm 9000 --capex-per-tpa 1000

Shipping rises to 1.73 and delivered to 9.55 USD/MMBtu; the round trip is 47.1 days.

Bottom-up capex with a region and sensitivity

lng-cost --bottom-up --region australia --steel-price 2400 --labour-rate 90 --sensitivity

A capex build-up table in USD million (steel, cement, labour, equipment, indirects, owner's, contingency, total) giving 1,311 USD per tonne/yr, and a +/-20% sensitivity per driver.

Full JSON for your own post-processing

lng-cost --json | head -20

Keys feed_gas, liquefaction_capital, fob_price, shipping, regas, delivered, a voyage block and a detail block echoing every input.

Shipping distance sweep through the Python API

from lng_cost import LiquefactionInputs, ShippingInputs, RegasInputs, estimate
for d in (3000, 6000, 9000, 12000):
    e = estimate(LiquefactionInputs(capacity_mtpa=5, capex_per_tpa=1000, feed_gas_price=3.0), ShippingInputs(distance_nm=d), RegasInputs())
    print(d, round(e.shipping, 2), round(e.delivered, 2), round(e.voyage['round_trip_days'], 1))

About 0.19 USD/MMBtu per 1,000 nm with these inputs. The README's Python example (feed gas 3.0) prints 9.0 at 9,000 nm, while the CLI example with the same distance and capex prints 9.55 because the CLI keeps the 3.50 feed-gas default; the 0.55 gap is 0.50 of feed gas grossed up by 1/(1-0.09).

Ways to use it

MethodHow it works
CLIlng-cost with --capacity-mtpa, --capex-per-tpa, --feed-gas-price, --discount-rate, --distance-nm, --charter-rate, --bunker-price, --regas-capex-per-tpa; add --bottom-up, --region, --steel-price, --cement-price, --labour-rate, --equipment-index, --sensitivity, --json.
Python APIestimate(LiquefactionInputs(...), ShippingInputs(...), RegasInputs()) returns an object with per-block costs, a voyage dict and a detail dict; CapexBuild, Prices, with_region and sensitivity drive the bottom-up mode; scale_capex applies the six-tenths rule.
Calibrate privatelyOverride the dataclasses from your own licensed benchmark data (capex per tpa, charter rates) and keep that data out of the public repo, as the README asks.
Through an AI assistantGive it README.md and src/lng_cost/ and ask it to loop inputs for a tornado chart or add a cost block.

Limits and honest caveats

  • All defaults, quantities, prices and regional multipliers are illustrative placeholders, not sourced benchmarks; docs/REFERENCES.md itself says its leads are from a web search and not yet read or verified. No figure here should be quoted as an industry number.
  • Screening-level (roughly Class 5) accuracy. No tax, royalty, inflation, financing during construction or contingency beyond what you put in capex; single-vessel voyage economics with no fleet sizing or idle time; no terminal tank, jetty, pipeline or upstream cost; no uncertainty analysis.
  • Fixed conversion assumptions: 52 MMBtu per tonne and 0.45 t per cubic metre; the reference plant scales with exponent 0.65.
  • No third-party benchmark data is bundled because it is proprietary; calibrate from your own licence and keep it out of the public repo.
  • Conceptual cost estimate, not engineering design. Not investment advice.
