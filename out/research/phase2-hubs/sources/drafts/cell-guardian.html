Why it is useful

  • Students, hobbyists and battery-software engineers get a readable, tested reference of how a BMS works end to end (cell model, EKF, SOH, balancing, power limits, supervisor state machine) without buying hardware or reading a commercial codebase.
  • It replaces ad-hoc scripts: one package with 112 passing tests, so you can change a chemistry or pack layout and see the consequences in simulation.
  • Evidence from the run: the full test suite passed in 3.6 s and the dataset-validation command ran in about 9 s on a laptop, with no accounts or downloads.
  • It generates its own Kaggle-schema battery datasets, so analysis code you write today works unchanged when you later swap in the real CSVs.

What it is for

cell-guardian simulates a battery pack the way a BMS controller would manage it: an Extended Kalman Filter estimates state of charge (SOC) from voltage and current, a separate estimator tracks state of health (SOH) as capacity and resistance fade, and a supervisor opens contactors on over-voltage, under-voltage, over-current, over-temperature and isolation faults.

It ships presets for an electric scooter (15S LFP), a lead-acid 4W retrofit, a modern LFP 4W and an electric bus, plus manufacturer-style profiles and driving-condition degradation projections. This is a simulation for learning and prototyping, not production BMS firmware.

Who it is for

  • Students and self-learners studying battery management and Kalman filtering
  • EV and storage startups prototyping pack logic before hardware
  • Data scientists who want realistic battery telemetry in the NASA, MIT and Kaggle schemas
Not for.
  • Safety-critical use: this is not certified BMS firmware and must not manage a real battery
  • Claims about real cell behaviour: the bundled validation data are synthetic, generated by the model itself
  • Engineering design: the content is conceptual, not an engineering design basis

Install

  1. Clone and enter the repo
    git clone https://github.com/herrrickshaw/cell-guardian.git
cd cell-guardian
  2. Create a virtual environment and install the dependencies
    python3 -m venv .venv && source .venv/bin/activate
pip install numpy pandas matplotlib scipy pytest

Quick start: commands and what you should see

Run the tests

python -m pytest -q tests

112 passed in about 4 seconds.

Generate synthetic Kaggle-schema datasets and validate the model against them

python -m bms.simulation --datasets

The vehicle comparison table, six dataset shapes, then a validation report with SOC, capacity-fade, voltage and RUL sections (about 9 seconds).

Run the default simulation of all vehicle presets (slow)

python -m bms.simulation

Per-vehicle charge/discharge simulations. On my laptop this took about 2 minutes 9 seconds, so run it when you have a coffee.

Limits and honest caveats

  • Conceptual simulation, not certified BMS firmware, and not an engineering design basis.
  • Validation uses synthetic data generated by the same cell model, so the very low errors (SOC RMSE 0.117 %, voltage RMSE 1.07 mV) show internal consistency only, not accuracy on real cells. I did not run the real Kaggle datasets.
  • The repo has no requirements.txt: you must install numpy, pandas, matplotlib, scipy and pytest yourself.
  • The default python -m bms.simulation run is slow (about 2 min 9 s here).
  • The comparison table shows 1.4 kWh for the scooter while its detail block prints 4.8 kWh (100 Ah).
  • The Kaggle-derived real datasets are not bundled and are not redistributed in this post.
