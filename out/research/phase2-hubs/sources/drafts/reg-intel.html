Why it is useful

  • Compliance analysts and researchers who read banking and insurance rules get a repeatable way to list what a Master Direction obliges a regulated entity to do, each item tied to a quote you can check.
  • It replaces trusting an LLM summary: a citation that is not a verbatim substring of the stored document is flagged as ungrounded, and a hash-chained ledger shows whether the record was edited afterwards.
  • Evidence from the run: all 8 tests passed in under a second offline, including a test where a made-up citation is correctly rejected, and the ledger check reported 'ledger chain intact'. A live fetch of one RBI listing entry also worked.
  • The repo reports its own recall and precision from draft gold labels, and says plainly that they are indicative until a person reviews them.

What it is for

Indian banks and insurers are bound by RBI Master Directions, which run to many pages. reg-intel is step 1 of a pipeline: fetch the directions politely, store the text, have an LLM pick out obligations (who must or must not do what, with any deadline), and accept an item only if its citation is found verbatim in the source text.

The default mode is line-indexed: the model selects numbered source lines and the citation is the line itself, which favours recall. A generate mode, where the model writes the quote, is also available and is the stricter test of grounding.

Output is not legal advice. Always read the cited source.

Who it is for

  • Compliance and risk teams in banks and insurers exploring LLM-assisted obligation registers
  • Researchers studying how to ground LLM extraction in source text
  • Developers who want a small example of a verbatim-citation gate and a hash-chained audit log
Not for.
  • Legal or compliance sign-off. It is not legal advice and the gold labels are unreviewed drafts
  • Anyone expecting a finished obligations database. Only two documents are labelled so far
  • Other regulators. The fetcher targets RBI Master Directions

Install

  1. Clone the repo.
    git clone https://github.com/herrrickshaw/reg-intel.git
cd reg-intel
  2. Create a virtual environment and install the dependencies. In the demo, pip install -e . failed at the build step (the repo has several top-level folders), so the dependencies were installed directly and the package was run from the repo folder, which works.
    python3 -m venv .venv
.venv/bin/pip install requests beautifulsoup4 openai pytest

Quick start: commands and what you should see

Run the offline tests.

.venv/bin/python -m pytest -v

8 passed in well under a second: citation gate, hallucinated-citation flagging, ledger tamper detection, listing parser, bad-JSON handling, line-indexed citation, precision override and lead-in detection.

Fetch one Master Direction (polite 2 second delay between requests).

.venv/bin/python -m reg_intel.cli fetch --limit 1

Prints the title it fetched and stores it in a local SQLite database.

Check the audit ledger.

.venv/bin/python -m reg_intel.cli verify

ledger chain intact

The verbatim-citation gate on a tiny source

extract.verify_citation(citation, source)
'report fraud to the RBI within 14 days'  -> True
'report fraud within 7 days'              -> False
'All branches must comply.'               -> True

Source text was 'Banks shall report fraud to the RBI within 14 days of detection. All branches must comply.' Whitespace differences are tolerated; paraphrases and wrong numbers are rejected.

Limits and honest caveats

  • Not legal advice. The tool lists candidate obligations; a qualified person must read the cited source.
  • The gold labels are drafts made by Claude and not human-reviewed. Recall and precision numbers are indicative only, and only two documents exist, so they are not held-out results.
  • In the default line-indexed mode the citation is the source line itself, so the grounding check is trivially satisfied and no longer measures precision on its own.
  • pip install -e . failed in the demo; run it from the cloned folder after installing the dependencies.
  • The repo notes that RBI's PDF host blocks scripted downloads; PDF-only documents must be downloaded manually in a browser.
  • The LLM extraction step was not run in the demo (no key), so extraction output is not shown, and the extract/report numbers above are the repo's own.
