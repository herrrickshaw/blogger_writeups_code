Why it is useful

  • Who benefits: students, e-mobility analysts and engineers who want a runnable reference of a battery management system (charge estimate, ageing, balancing, thermal limits, fault handling).
  • What it replaces: stitching together a cell model, a Kalman filter and a wear model from scratch. The vehicle comparison, degradation, cold-weather and 10-year projection runs are one command each.
  • Evidence from the run: 112 tests passed in 4.2 seconds, and the dataset validation printed a five-part report in about 8 seconds on a laptop.
  • It also ships a cleaning notebook that turns the NASA battery .mat files into CSVs, which is useful if you download the NASA data yourself.

What it is for

The bms package models a lithium or lead-acid pack: a two-RC equivalent-circuit cell, an Extended Kalman Filter for state of charge, capacity and resistance fade for state of health, passive balancing, thermal control, power limits and a supervisor that opens the contactor on faults. Run python -m bms.simulation with a flag to see each part.

It is a teaching and prototyping tool. It is simulation only, not engineering design: do not use it to size or certify a real pack.

Who it is for

  • Students and engineers learning how a BMS works
  • EV and e-mobility analysts who want a runnable reference
  • Non-programmers who want an AI assistant to explain each algorithm
Not for.
  • Running or certifying a real battery pack. This is a conceptual simulation, not firmware and not an engineering design.
  • Claiming real-world accuracy from the validation numbers. They come from synthetic data generated to match the schemas of the Kaggle files.
  • Predicting the life of a specific real cell.

    git clone https://github.com/herrrickshaw/ev-battery-management-sim.git
cd ev-battery-management-sim
  2. Create an environment and install
    python3 -m venv .venv && source .venv/bin/activate
pip install numpy pandas pytest scipy matplotlib

Quick start: commands and what you should see

Run the tests

python -m pytest -q

112 passed.

Compare the vehicle classes

python -m bms.simulation --vehicle 2W

A comparison table of the four vehicle classes, then the scooter run.

Run the degradation simulation

python -m bms.simulation --degradation

Cycle-by-cycle table of capacity and resistance fade for a scooter and a bus.

Run the dataset validation (synthetic)

python -m bms.simulation --datasets

Six synthetic datasets are generated and a five-part validation report is printed.

Limits and honest caveats

  • The six 'Kaggle validation' checks run on synthetic data generated to match the Kaggle file layouts, and the script prints this itself. They are not evidence of accuracy on real cells. Because the fitted fade rate (0.1001 %/cycle) matches the rate used to generate the data, check 2 is partly circular.
  • The NASA notebook and real-data validation need Kaggle downloads and credentials; not run here. data/kaggle/ is gitignored.
  • No requirements.txt: numpy, pandas, scipy, matplotlib and pytest had to be installed by hand.
  • Quirk found: in the distributed-BMS check, module 3 is detected as degraded (SOH 85 % versus 97.3 %) yet 'Degraded alerts' is 0, so the alert path did not fire for that module.
  • Degradation is a linear, accelerated model; the script's own label says 0.1 % per cycle is not a real LFP rate.
  • This is a conceptual simulation, not engineering design, firmware or a safety case.
