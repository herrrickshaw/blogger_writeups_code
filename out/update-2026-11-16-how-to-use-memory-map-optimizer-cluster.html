Why it is useful

  • Who benefits: people who keep a large pile of markdown notes or an AI-assistant memory folder and a graph of how things link, and want structure and duplicates found automatically.
  • What it replaces: counting and merging near-identical notes by hand, and a graph tool whose community detection returned zero.
  • Evidence from the run: on a synthetic 60-node graph with three planted groups, the cluster command found exactly three communities of 20 nodes each in 0.14 seconds; all 14 bundled checks passed.
  • The embedding, search and dedup steps need a downloaded model of about 1.5 GB and were not run here (see limits).

What it is for

The tool has five commands. cluster runs Leiden community detection on a graph JSON with nodes and edges. embed indexes markdown files with a sentence-embedding model. search combines keyword (BM25) and embedding ranks, with an optional reranker. dedup groups near-duplicate files by cosine similarity. report writes an HTML overview.

It was written for one person's Claude Code memory setup, so default paths point at ~/.graphify and ~/.claude. Pass your own paths to use it elsewhere.

Who it is for

  • People maintaining a large markdown notes or memory folder
  • Developers who want a small, readable example of Leiden clustering and hybrid search
  • Non-programmers who want an AI assistant to run it on their notes
Not for.
  • Notes you cannot send to a model download or process locally; check the model licence first.
  • Trusting dedup output blindly. The README says to sanity-check search results on a small subset first.
  • A drop-in replacement for graphify or qmd. It only reads and writes similar files.

Quick start: commands and what you should see

Run the bundled checks

python test_memory_map_optimizer.py

A line per check ending in ALL TESTS PASSED.

Cluster a graph file

python memory_map_optimizer.py cluster --graph my_graph.json --write-back --out clusters.json

A line such as '60 nodes, 213 edges -> 3 communities (modularity 0.6082)' and a size per cluster.

Index, search and dedupe notes (needs the model download)

python memory_map_optimizer.py embed --memory-dir "./notes/**"
python memory_map_optimizer.py search "token routing" --rerank
python memory_map_optimizer.py dedup --threshold 0.85

An index file, ranked results, and groups of near-duplicate files.

Limits and honest caveats

  • Only the cluster command and the bundled checks were run live. embed, search, rerank, dedup and the real report need a large model download and were not run.
  • The README states the build sandbox could not download the model, so embed has never been confirmed end to end by the author; the logic of search and dedup is tested with hand-built vectors.
  • Defaults point at the author's own ~/.graphify and ~/.claude paths; supply your own.
  • --write-back edits your graph JSON in place. Work on a copy.
  • Leiden results depend on a seed and resolution; different settings give different community counts.
  • Notes are processed by a local model; check licences of the Qwen and BGE models you choose.
