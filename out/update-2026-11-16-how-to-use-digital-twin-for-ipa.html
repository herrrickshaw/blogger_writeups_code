What it is for

Anyone who has tried to answer 'which central and state incentives apply to my project, and do they stack?' knows the answers sit across dozens of ministries, state portals and PDFs. This repo collects them into numbered layers, each a JSON file. Every claim carries a note on how it was verified, and access failures (blocked sites, JavaScript-only portals) are recorded as data rather than skipped.

The layers build on each other. Source networks and portal directories feed the incentive catalogs. The catalogs are normalised into one flat index of 312 instruments. A separate layer records which schemes stack, exclude or feed each other. A SQLite database links companies to filings, clearance activity, credit ratings and news. Monitors, watchlists and lead lists sit on top.

The demo only read data and ran one offline rebuild (on a scratch copy). It did not call any live government site and did not run the network-dependent layer builders.

Who it is for

  • Investment-promotion teams, analysts and consultants who need a structured starting point for India incentive research
  • Researchers who want a citable, diffable dataset of schemes and their stacking rules
  • Developers who want to build dashboards or tools on top of JSON layers and a SQLite file
Not for.
  • Legal, tax or investment advice. This is public data, not advice; check the official notification before acting
  • Real-time scheme status. Open and closed windows change, and live layers need network access that some Indian sites block
  • Treating stressed-asset or lead flags as conclusions. They are screening aids that need manual review

  1. Clone the repo.

cd digital-twin-for-ipa
  2. Nothing to install to read the data. Optional analysis extras:
    python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

Quick start: commands and what you should see

Summarise the flat instrument index.

python3 - <<'X'
import json,collections
d=json.load(open('layers/13_flat_instrument_index.json'))
print('count:',d['count'],'| by_tier:',d['by_tier'])
for k,v in collections.Counter(x['offering_entity'] for x in d['instruments']).most_common(6): print(v,k)
X

count: 312 with by_tier central 195 and state 117; the busiest offering entities were Ministry of Finance (12), Tamil Nadu (9), Telangana (9).

Count companies in the SQLite database (read-only).

sqlite3 -readonly -header -column data/companies.db "select count(*) companies, sum(is_india_entity) india_filers, count(distinct country) countries from companies;"

1849 companies, 1483 Indian filers, 48 countries (numbers as of the 18 October 2026 demo).

See the stressed-asset flags.

sqlite3 -readonly -header -column data/companies.db "select event_flag, count(*) n from stressed_assets group by 1 order by n desc;"

73 rows in grade_check_in_python, then 4 rating_darkness, 2 downgrade, 1 watch_negative, 1 sub_investment_grade, 1 litigation_or_regrade.

Regenerate the scheme catalogue. This writes into docs/, so copy the repo first if you want to keep it clean.

python3 scripts/build_catalogue.py

catalogue: 312 instruments -> docs/SCHEME_CATALOGUE.md

Ways to use it

MethodHow it works
Read the layersOpen any file in layers/ as JSON. The README has a table of what each layer holds, and the National Dashboard page in docs/ combines them.
Query the databasedata/companies.db is a plain SQLite file with tables for companies, filings, clearances, credit ratings, news and lead scores, plus a stressed_assets view.
Refresh from the command linescripts/refresh_twin.py has subcommands such as catalogue (offline) and routes, nsws or weekly (these need the network).
Colab notebookThe README links a Colab quickstart notebook in notebooks/.
Via an AI assistantPoint an assistant at README.md and layers/13_flat_instrument_index.json and ask it to filter, compare states or explain stacking rules.

Sample prompts for your AI assistant

Copy, paste and edit the parts in [brackets].

  • Read README.md and explain what each layer of this twin contains, in plain English, in one table.
  • Using layers/13_flat_instrument_index.json, list all state-tier instruments for Tamil Nadu and Telangana and compare what companies get.
  • Using layers/10_interlinkages.json, which schemes can be stacked with the PLI scheme and what is the legal anchor?
  • Write a read-only SQLite query on data/companies.db that lists non-Indian companies with a lead score tier, and explain the columns.
  • Which layers need network access to rebuild, and which sites does the repo say block automated access? What would break offline?
  • Check the README totals against the actual database and layer files and list any numbers that have drifted.

Limits and honest caveats

  • This is public data, not investment or legal advice. Verify every scheme against the official notification before acting.
  • The repo has no automated test suite. The demo's checks were a JSON parse of all 103 layer files and an offline catalogue rebuild.
  • Several live sources are blocked or crawling-sensitive (for example Invest India, MCA and zaubacorp). The demo did not call them; the twin records access failures as data.
  • README totals lag the data: the README says 1,785 companies while the database held 1,849 on the demo date.
  • Most credit-rating rows (73 of 82) fall in a 'grade_check_in_python' bucket, so the stressed-asset flag needs manual review.
  • Open or closed status of a scheme is a snapshot and changes; many instruments are not verified on site (the index has a verified_on_site field).
