Thirteen small repositories each solve one narrow problem: falling back to a local model when Claude is unavailable, checking an LLM’s citations, logging token cost, searching maritime reports offline, testing a warehouse backfill, finding duplicate Git LFS storage, checking blog posts for broken code, or freeing Mac disk space safely. This guide says what each one does, the command to start with, and what its own guide found it cannot do.

Thirteen Small Open-Source Tools for Developers and AI Users, From a Local Claude Fallback to an LFS Duplicate Audit, and What Each One Is For

These thirteen repositories are small and single-purpose. Most were written to fix a problem their author actually hit: a Claude rate limit in the middle of a long job, an LLM check that marked a correct extraction as ungrounded, a GitHub LFS quota used up by backup copies, a Mac disk at 99%, and defects that reached this blog’s own published posts.

They are for developers, data engineers and heavy users of AI assistants who want a working example to read or reuse. Several are also usable by non-programmers who hand the repository to an AI assistant and ask in plain language. Many were demonstrated on synthetic data, mock servers or dry runs, so each section says what was actually run, and when.

Working with LLMs and AI assistants

claude-lmstudio-router: fall back to a local model when Claude is unavailable

There are two tools. router.py tries the Claude API, retries twice on a 429 or 529 error, then sends the same prompt to a model served by LM Studio, and logs each call to router_log.jsonl. claude_code_proxy.py translates between the Anthropic API that Claude Code speaks and the OpenAI API that LM Studio speaks, so the whole agent can run offline on a local tool-calling model. You load the model and start LM Studio’s server yourself. The guide’s demo of 18 October 2026 used a canned stand-in server, not LM Studio.

Start here. Run one prompt (needs pip install anthropic; set ANTHROPIC_API_KEY for the Claude path).

python -I router.py --prompt "Summarize: tariffs"

With no key and no LM Studio it fails honestly: it reports both failures, prints ‘FAILED: Both Claude and local LM Studio failed’ and logs engine=none. When the local server answers, the output says ‘Answered by: LOCAL’ and the log shows engine=local.

Code: github.com/herrrickshaw/claude-lmstudio-router. Main limitation: local models are weaker and slower, so treat fallback output as a draft. The proxy needs a tool-calling model and drops image blocks. Text goes to Anthropic whenever Claude answers. No unit tests ship with the repo.

llm-extract-citation-fix: LLM extraction that checks its own citations

llm_extract.py exposes extract_structured(text, schema): it asks a Groq model (Gemini as fallback) for fields plus citations, checks each citation against the source, and adds a _grounding map. The fix in this repo makes the check accept list fields, where each item carries its own quote; the old check marked such correct extractions as ungrounded. The verifier runs offline with no key. Live extraction needs your own Groq or Gemini key and was not run in the guide.

Start here. Check a citation against source text, with no key.

python3 -c "from llm_extract import _verify_citation as v; src='TCS  Qty 5   Avg 3200.50'; print(v(['TCS  Qty 5   Avg 3200.50'], src), v(['WIPRO Qty 7'], src))"

True False: a list of per-item quotes passes only if every quote is in the text (run of 3 November 2026).

Code: github.com/herrrickshaw/llm-extract-citation-fix. Main limitation: a grounded field proves that the quote exists, not that a derived value such as a midpoint is right. The guide notes that the default model names in the file are retired, so set GROQ_MODEL and GEMINI_MODEL yourself. There are no tests, requirements file or packaging.

prompt-efficiency-tracker-public: log Claude Code token cost, and notice when logging stops

The hook writes one row per turn into a local SQLite table, split by project and by main agent versus subagent, and marks a turn tool_error if a tool result errored since the last logged message. The heartbeat script reports when the hook has dropped out of settings.json or the database has gone stale; a macOS launchd plist runs it daily. In the guide’s run of 3 November 2026, in a throwaway home directory with a synthetic transcript, running the hook twice left exactly two rows.

Start here. Run the heartbeat (try it first with a throwaway HOME).

python3 scripts/heartbeat_check.py; tail -1 "$HOME/.ruflo/logs/heartbeat.log"

It always exits 0. On an empty home the log line lists two problems: settings.json missing, and token_usage.db does not exist. Once the hook was wired in the demo home, it reported ok.

Code: github.com/herrrickshaw/prompt-efficiency-tracker-public. Main limitation: the hook does not create its token_usage table and the schema is not in the repo, so you must create it. Costs are estimates from a hard-coded price table, not billing data. Scheduling and notifications are macOS-only.

ship2shore_rag: offline, cited answers from open maritime reports

It collects arXiv papers, Wikipedia, UK MAIB and US NTSB accident reports, and your own PDF or Word files, splits them into passages, and combines meaning-based and keyword search with a reranking step. Ashore it uses Postgres with pgvector; on a vessel it uses one SQLite file. Writing an answer with Claude is optional; without a key it lists ranked passages with their sources. The repo ships a snapshot of 125 documents, and the install (sentence-transformers and two small models) needs about 1 GB of disk.

Start here. With STORAGE_BACKEND=sqlite and SQLITE_PATH=snapshots/ship2shore.sqlite3 set in .env, ask a question without an API key.

python3 cli.py ask "What is a bill of lading and what does it do?" --no-generate --top-k 3

Three passages. In the guide’s run of 18 October 2026, two came from the Wikipedia article on the bill of lading and one from the article on charterparties. On the repo’s 17 test questions, recall@5 was 0.76 without reranking and 0.82 with it.

Code: github.com/herrrickshaw/ship2shore_rag. Main limitation: the corpus is small: questions about engine-room fires returned only loosely related reports, and 17 test queries make the scores indicative, not a benchmark. It does not replace statutory logs, and its web API accepts requests from any origin, so keep it on localhost.

memory-map-optimizer: cluster a knowledge graph, search and dedupe notes

It has five commands. cluster runs Leiden community detection on a graph JSON; embed indexes markdown files with a sentence-embedding model; search combines BM25 keyword and embedding ranks, with an optional reranker; dedup groups near-duplicate files by cosine similarity; report writes an HTML overview. Defaults point at the author’s own Claude Code memory paths, so pass your own.

Start here. Cluster a graph file.

python memory_map_optimizer.py cluster --graph my_graph.json --write-back --out clusters.json

A line such as ‘60 nodes, 213 edges -> 3 communities (modularity 0.6082)’ and a size per cluster. The worked example below shows the full run.

Code: github.com/herrrickshaw/memory-map-optimizer. Main limitation: only cluster and the bundled checks were run in the guide. The other commands need a model download of about 1.5 GB, and the README says embed was never confirmed end to end. --write-back edits your graph JSON in place, so work on a copy.

Data pipelines and testing

data-source-mining: World Bank indicators and mandi prices in one DuckDB file

mine_underused_sources.py pulls 12 World Bank indicators (GDP, growth, inflation, agriculture share, trade, energy mix, FDI and others) for India and six comparison economies, and the data.gov.in Agmarknet resource using the public sample key that data.gov.in documents. It needs Python and the duckdb package, and no account. The committed database was pulled on 21 July 2026 and has 4,532 World Bank rows and 4 mandi rows.

Start here. Pull the World Bank leg only.

.venv/bin/python mine_underused_sources.py --wb-only

One line per country, then ‘worldbank_indicators: N rows’ and a table list. It makes about 84 API calls and takes a few minutes.

Code: github.com/herrrickshaw/data-source-mining. Main limitation: run in the cloned folder, it overwrites the World Bank table in the committed database, so copy the folder first. The mandi sample key returns a small, rate-limited sample. It mines a fixed pair of sources and is not a general discovery tool.

ltm-warehouse-tests: test a price-history backfill on a throwaway Postgres

run_tests.sh creates a test database, applies a schema that mirrors the real tables, and seeds synthetic symbols that encode past bugs: a ticker already carrying a suffix, a symbol under two countries, an NSE series switching mid-history. It runs three test files and drops the database even if a test fails. The tests check deduplication, that low-fidelity estimates go to a separate table, that a dry run never persists, and that the NSE tier fires only for India. No API keys are needed.

Start here. Run the whole suite against a local Postgres (install requirements.txt with "sqlalchemy<2.1" first).

./run_tests.sh

It ends with ‘All tests passed.’ and drops the database. In the guide’s run of 19 October 2026 on a throwaway Postgres 17, all three test files passed.

Code: github.com/herrrickshaw/ltm-warehouse-tests. Main limitation: with requirements.txt as written, a fresh install picked SQLAlchemy 2.1.5 and seeding failed, hence the pin. The script ignores the port in PG_ADMIN_URL, so set PGPORT and PGHOST for a non-default port. Live Yahoo, NSE and SerpApi calls are not exercised.

repo-data-dedup: find duplicate Git LFS storage across your repos

scripts/audit_lfs.py makes a filtered clone of each repo that reads only the small pointer files, writes lfs_inventory.csv (every pointer, its size and whether HEAD still uses it) and repo_summary.csv, and prints total stored, total unique and cross-repo duplicate waste. It needs Python 3, git and a logged-in GitHub CLI. On a synthetic three-repo account in the guide’s run of 19 October 2026, it counted 1.83 GB stored against 0.71 GB unique.

Start here. Audit your own account, read-only. Replace <owner> with your GitHub user or organisation.

mkdir -p ~/lfs_audit && cd ~/lfs_audit
python3 /path/to/repo-data-dedup/scripts/audit_lfs.py <owner> ~/lfs_audit/clones

One progress line per repo, then the three totals; the two CSVs appear in the current folder.

Code: github.com/herrrickshaw/repo-data-dedup. Main limitation: it counts pointers; it does not prove that a copy is safe to delete. The repo’s delete_archive_twins.sh --run deletes real repositories from a list hard-coded for the author’s account, so read it and use only its default dry run. LFS storage is freed only by deleting repositories.

Publishing, design and process

blog-consistency-check: is this blog post broken?

It lists posts through the public Blogger feed, downloads each with curl, and applies 10 static rules: 4 blockers (such as JavaScript that does not parse, or a dark palette with no light-mode lock), 2 major and 4 minor. CHECKLIST.md explains each rule. An optional Playwright pass adds contrast and overflow checks. It needs Python 3, curl and node.

Start here. Audit one public post.

python3 audit.py --url <post URL>

It writes out/report.md and out/report.json and prints a count of BLOCKER failures. In the guide’s run of 19 October 2026, one live post showed 1 BLOCKER and 1 MINOR, both about its CSS.

Code: github.com/herrrickshaw/blog-consistency-check. Main limitation: it is hard-coded to blog.vertistratsolution.com, and several rules are specific to this blog. The static pass reads the HTML source, so a CSS finding is a signal to inspect, not proof of a visible fault. The fix scripts edit content and were not run in the guide.

research-design-system: one set of design tokens, four themes

Components use only semantic tokens such as --c-text and --c-accent, and each theme rebinds about a dozen of them. The same page switches between the bulletin, report, reportage and slate themes by changing one stylesheet and one body class; the guide rendered all four on 19 October 2026. Templates for a report, a bulletin and a dashboard, a component gallery and A4 print rules for WeasyPrint are included. There is no JavaScript or build step.

Start here. Start from a template and open it.

cp templates/report.html my-report.html   # then fix the ../ paths or keep the file inside the repo
open my-report.html

A report page with a masthead, stat tiles, a table and side and warning boxes. Load the stylesheets in this order: tokens, theme, components, print.

Code: github.com/herrrickshaw/research-design-system. Main limitation: it is a starter kit, not a brand system, and only CSS. Dark mode is opt-in through a data-theme attribute, not the operating-system setting. Numbers in the shipped templates are placeholders, not data. The WeasyPrint path was not tested in the guide.

delivery-playbook: a field guide for choosing and fixing a software process

The page compares Waterfall, V-Model, Spiral, Scrum, Kanban, XP and DevOps. It offers a two-question fit-finder (how often requirements really change, and how costly a mistake is once shipped) and six named failure modes, such as Zombie Scrum and Watermelon status, each with a fix. It also covers computer-science theory applied to product decisions, Domain-Driven Design, TOGAF and a testing playbook. There is nothing to install.

Start here. Open the page.

open index.html   # macOS; on Linux use xdg-open, on Windows double-click the file

The fit-finder places a project in one of four quadrants. High stakes with unclear scope points to Spiral; low stakes with unclear scope to Scrum, XP or Lean Startup.

Code: github.com/herrrickshaw/delivery-playbook. Main limitation: it is a field guide with the author’s opinions, not an official Scrum, SAFe or TOGAF text, so check the primary sources it links. The live copy is not auto-synced with the repo.

Machine housekeeping

cache_memory_cleaner: free Mac disk space without losing data

Its key command, classify, reads git status, whether a running process has the path open, whether it sits in a cloud-sync folder, whether the name looks like a personal scan, and how long since anything changed, then prints a tier and the reason. It never deletes. Other commands act on the tiers: clean-caches, compress-local (needs afsctool) and archive-evict, which uploads to your cloud with rclone, checks the bytes, and only then deletes. Put DRY_RUN=1 in front of any command to preview it.

Start here. Ask which tier a folder belongs to (read-only).

./cache_memory_cleaner.sh classify path/to/venv

In the guide’s demo of 18 October 2026, a virtual environment came back as Tier 1 (permanent local, compress in place) and a __pycache__ folder as Tier 4 (delete immediately).

Code: github.com/herrrickshaw/cache_memory_cleaner. Main limitation: classify is a heuristic, so read its reason before acting. Never point the archive remote at a path that another rclone sync job mirrors: in the author’s case a sync wiped four verified archives. archive-evict deletes originals and was not run in the demo.

transmission-client: control a Transmission daemon from a CLI, a web page or Python

You can list, inspect, add, start, stop and remove torrents from a terminal, from a web page on 127.0.0.1:5000, or from your own Python code. The client handles Transmission’s session-id handshake for you: it catches the 409 reply, stores the id and retries. It needs Python 3.9 or newer and a running daemon. Use it only for content you have the right to download and share.

Start here. List torrents (after pip install -e . and setting TRANSMISSION_HOST and TRANSMISSION_PORT).

transmission-cli list

A table with ID, STATUS, DONE, SIZE, DOWN, UP and NAME columns. The guide’s run of 19 October 2026 used a mock daemon, not a real one.

Code: github.com/herrrickshaw/transmission-client. Main limitation: it was shown against a mock only, so behaviour with a real daemon is untested. The repo has no tests, and the session id is not cached between runs. The README’s development setting --allowed "" opens the RPC port to every host; do not use it on an exposed machine.

Worked example: clustering a graph (memory-map-optimizer)

This is the run recorded in the memory-map-optimizer guide on 19 October 2026, from a fresh clone in a throwaway virtual environment. The guide installed only python-igraph, leidenalg, rank-bm25 and numpy, which is enough for the checks and the cluster command; the full requirements.txt also pulls in sentence-transformers.

1. Get the code and an environment.

git clone https://github.com/herrrickshaw/memory-map-optimizer.git
cd memory-map-optimizer
python3 -m venv .venv
source .venv/bin/activate

2. Run the bundled checks.

python test_memory_map_optimizer.py
test_leiden_finds_real_communities OK (4 communities found, planted 4, modularity 0.721)
test_hybrid_search_ranks_relevant_doc_first OK
test_find_duplicate_groups_merges_transitively OK
test_report_runs_without_index_or_clusters OK
ALL TESTS PASSED

Trimmed to four of 14 lines. The search and dedup checks use hand-built vectors, not a real model.

3. Cluster a test graph. The guide built a random graph of 60 nodes in three planted groups of 20: dense inside each group (35% of node pairs linked) and sparse between them (1%).

python memory_map_optimizer.py cluster --graph g.json --write-back --out clusters.json
60 nodes, 213 edges -> 3 communities (modularity 0.6082)
  cluster 2: 20 nodes
  cluster 0: 20 nodes
  cluster 1: 20 nodes
wrote clusters.json
wrote community assignments back into g.json

The tool recovered the three planted groups exactly, in 0.14 seconds. clusters.json records the node and edge counts, the modularity, the cluster sizes and each node’s cluster, and --write-back added a ‘community’ field to every node in g.json. Leiden results depend on the seed and resolution, so other settings can give a different number of communities.

What these tools do not do

  • Most were not tested at full scale. The guides ran them against a mock Transmission daemon, a canned stand-in for LM Studio, a synthetic GitHub account, a synthetic transcript and a random graph. Behaviour on real systems is less tested than the outputs suggest.
  • Some can delete things. archive-evict deletes originals, delete_archive_twins.sh --run deletes repositories, and the blog checker’s fix scripts edit posts. Use the dry runs and read the scripts first.
  • The LLM tools check where an answer came from, not whether it is right. A grounded citation proves that a quote exists; a local fallback answer is a draft; a 17-question retrieval test is indicative.
  • Costs and scores are estimates. The token tracker’s cost comes from a hard-coded price table, not billing data.
  • Several are tied to the author’s setup. The blog checker is hard-coded to this blog, the memory tool and the heartbeat default to the author’s paths, and the archive-twin list names the author’s repositories.
  • Some ship without tests. The guides found no tests in claude-lmstudio-router, transmission-client or llm-extract-citation-fix.
  • They are not professional advice. The data miner returns raw open statistics, not investment advice; ship2shore_rag is not for legal, safety-critical or class decisions; delivery-playbook is not a certification text.
