Why it is useful

  • Heavy Claude Code users get a local, queryable record of tokens and estimated cost per turn, split by project and by main agent versus subagent, instead of guessing where usage goes.
  • It replaces a tracker whose status column was hardcoded to success: here a turn is marked tool_error if a tool result was an error since the last logged message, a rough but real outcome signal.
  • The heartbeat catches the failure that actually happened to the author: the hook silently dropped from settings.json. In the demo it reported both problems on an empty home and ok once wired.
  • Evidence from the run: running the hook twice on the same transcript left exactly two rows, so de-duplication works.

What it is for

The repository holds the hook (hooks/claude-code-usage-hook.py), a heartbeat checker (scripts/heartbeat_check.py), a macOS launchd plist for a daily check, and two promptfoo prompt-regression pilots.

This post demonstrates the hook and heartbeat in an isolated fake home directory with a synthetic transcript, so no real usage data is involved. The promptfoo pilots call paid LLM APIs and were not re-run; the committed result file is quoted instead.

Who it is for

  • Claude Code users who want their own usage and cost log
  • Developers who want a pattern for a never-blocking hook plus a watchdog
  • People learning prompt-regression testing with promptfoo
Not for.
  • Billing: costs are estimates from a hard-coded price table in the script
  • Teams or shared dashboards: it writes a local SQLite file
  • Windows or Linux scheduling: the daily job is a macOS launchd plist and notifications use osascript

Install

  1. Clone and enter the repo
    git clone https://github.com/herrrickshaw/prompt-efficiency-tracker-public.git
cd prompt-efficiency-tracker-public
  2. Copy the hook and heartbeat somewhere stable, then register Stop, SubagentStop and SessionStart hooks in your Claude Code settings.json (the README describes the shape)
    mkdir -p ~/.ruflo/hooks
cp hooks/claude-code-usage-hook.py ~/.ruflo/hooks/
  3. Try it first with a throwaway HOME so nothing real is touched
    export HOME="$(mktemp -d)"   # in a scratch shell only

Quick start: commands and what you should see

Run the heartbeat on an empty home

python3 scripts/heartbeat_check.py; tail -1 "$HOME/.ruflo/logs/heartbeat.log"

Exit code 0 always. The log line lists the problems: settings.json missing and token_usage.db does not exist.

Feed the hook a Stop event

echo '{"session_id":"demo","transcript_path":"/path/to/transcript.jsonl","hook_event_name":"Stop","cwd":"/path/to/project"}' | python3 hooks/claude-code-usage-hook.py

No output on success; rows appear in token_usage. Without the table it prints a db error and exits 0.

Sample prompts for your AI assistant

Copy, paste and edit the parts in [brackets].

  • Explain how the Stop hook decides status tool_error versus success and what it misses.
  • Write a SQL schema for the token_usage table that matches the hook's INSERT statement.
  • Adapt the heartbeat to Linux using cron and notify-send instead of launchd and osascript.
  • Add a weekly SQL report of cost by project and model from token_usage.
  • Update the PRICES table in the hook to current model prices and explain the cache multipliers.

Limits and honest caveats

  • Costs are estimates from a hard-coded price table, not billing data.
  • The hook does not create the token_usage table; with no table it prints a db error and logs nothing. The schema is not in the repo, so you must create it yourself.
  • The tool_error flag is approximate: it fires if any tool result errored since the previous logged message.
  • The heartbeat paths and launchd plist are written for macOS and a fixed home layout.
  • The demo used a synthetic transcript and a throwaway home; no real usage was logged or shown.
  • The promptfoo pilots need paid API keys and were not re-run; the second pilot is documented as not yet live.
