Why it is useful

  • Market researchers, analysts and students who need a country-by-sector count of registered companies get a documented, licence-aware way to build one from open data, without buying a commercial contact database.
  • It replaces ad-hoc downloading and merging: one build.py handles fetch, load, dedupe and list generation, with a normalised sector scheme across SIC, NACE, NIC and Damodaran industries.
  • Evidence from the run: the committed count tables sum to 18,170,810 companies across 132 countries, and in the 6 sample files every row carried a sector.
  • The big registries are France (11.26M), the UK (5.17M) and Norway (1.17M); India has about 180,000 only because it comes from companies that hold an LEI, not the full register. Read the counts with that in mind.

What it is for

Counting companies by country and sector is a common starting point for market sizing and supplier mapping. This repo builds that table from public registries and records each source's licence in SOURCES.md.

The data itself (1.2 GB of CSV and a 1.4 GB DuckDB) is not in git. You rebuild it with build.py. The repo ships 200-row samples per source and two count tables in docs/.

This is the public copy: the defence-industry sample and the Estonia sample were removed from the data and history because their redistribution terms were unchecked; the code that builds them stays. The post uses aggregate counts only and shows no company names.

Who it is for

  • Analysts doing market sizing or supplier mapping by country and sector
  • Data engineers who want a worked multi-registry dedupe pipeline in DuckDB
  • Students of open company data and industry classification schemes
Not for.
  • Sales prospecting or contact lists: the data holds company records, no contacts, and registry sources have their own terms
  • Treating counts as a complete census: some countries are missing and India is partial
  • Redistributing the data without checking each provider's current licence

Install

  1. Clone the repo.
    git clone https://github.com/herrrickshaw/company-database-public.git
cd company-database-public
  2. Create a virtual environment and install the requirements.
    python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
  3. Optional full rebuild (large downloads, not run in the demo). Follow the README for the other sources.
    python3 build.py fetch gleif && python3 build.py fetch ch
python3 build.py dedupe && python3 build.py lists

Quick start: commands and what you should see

Count the shipped samples by source with DuckDB.

.venv/bin/python -c "import duckdb; print(duckdb.sql(\"select sources, count(*) rows, count(distinct sector) sectors from read_csv_auto('samples/*.csv', union_by_name=true) group by 1 order by 2 desc\").df())"

Six main sources with about 200 rows each and 13 to 18 distinct sectors apiece.

Total companies by country from the committed count table.

.venv/bin/python -c "import duckdb; print(duckdb.sql(\"select country, sum(companies) n from read_csv_auto('docs/counts_by_country_sector.csv') group by 1 order by n desc limit 6\").df())"

France, the UK, Norway, Estonia, India and China at the top.

Limits and honest caveats

  • The database itself is not in git; only 200-row samples and count tables are. A full rebuild needs several GB and was not run in the demo.
  • Running python3 build.py with no arguments crashes with an IndexError instead of printing usage; read the README's Rebuild section for the commands.
  • Registry sector can mislead for holding companies, and name-based matching can miss merges or, rarely, wrong-merge.
  • India is partial: about 170,000 companies from those with an LEI, not the full register. Finland, Brazil, Denmark, Singapore and the US SEC are not covered.
  • Licences differ by provider (GLEIF CC0, Companies House OGL v3, Etalab, NLOD). Check each provider's current terms before redistributing, and cite them.
  • The count table still reports the 2,477 defence rows although that sample is not in this public copy, and it lists 22 sector labels (21 sections plus unclassified).
