Why it is useful

  • Developers and analysts who want to see how an event-driven portfolio monitor could be structured get a short, readable event bus and a long set of architecture documents.
  • It replaces starting from a blank page: the repo has a TOGAF-style blueprint, workflow descriptions, a FastAPI skeleton with portfolio, risk, rebalance, alert and report routers, and sample OHLCV files for eight markets.
  • Evidence from the run: feeding the sample Korea prices through the bus produced 20 price-move events for one ticker at a 1.5 percent threshold, each delivered to a subscriber and kept in history.
  • It is useful as a design reference, not as a finished product. Most of the README describes an architecture, and the sample prices are generated, not real.

What it is for

Event-Driven Stock Analysis is a design-first repository. The README describes a multi-market portfolio monitor with risk metrics, rebalancing and alerts. The code that exists is a FastAPI backend with routers and services, and an EventBus plus a PortfolioMonitor class for publishing and watching market events.

The sample data in data/market_data is a set of compressed CSV files with date, market, ticker, open, high, low, close and volume for eight markets.

Who it is for

  • Developers studying event-driven design for finance back ends
  • Students who want a documented example of a layered architecture
  • Researchers who need a small, shareable OHLCV format for testing code
Not for.
  • Investment advice: this is not investment advice, and nothing here is a recommendation to buy or sell
  • Real market analysis: the sample prices are synthetic
  • Production use: the README says implementation is ready to start, and the tests do not run yet

Quick start: commands and what you should see

Start the API with SQLite and read the root route

DATABASE_URL=sqlite:///./test.db uvicorn main:app --reload
# then open http://localhost:8000/docs

The app logs 'Database initialized' and 'API routers registered'. GET / returns the app name, version 0.1.0 and the docs path.

Publish events from the sample data (my demo script, not in the repo; save it as demo.py in backend/ and run it)

import asyncio, sys
sys.path.insert(0, "events/..")
from events.event_bus import EventBus, MarketEvent
from events.portfolio_monitor import PortfolioMonitor
import pandas as pd, gzip
df = pd.read_csv("../data/market_data/korea_ohlcv.csv.gz")
t = df.ticker.unique()[0]; d = df[df.ticker==t].sort_values("date")
d["ret"] = d.close.pct_change()
bus = EventBus(); mon = PortfolioMonitor(); mon.add_tickers([t], "korea")
seen=[]
bus.subscribe("price_move", lambda e: seen.append(e))
async def main():
    for _, r in d.iterrows():
        if abs(r.ret) > 0.015:
            await bus.publish(MarketEvent("price_move", t, "korea", {"date": r.date, "ret_pct": round(r.ret*100,2)}))
asyncio.run(main())
print("watched:", mon.watched(), "| monitoring:", mon.is_monitoring(t))
print("events seen:", len(seen), "| history:", len(bus.history))
for e in seen[:5]: print(e.type, e.ticker, e.market, e.data)

# run:
python demo.py

Prints the watched ticker and a count of events received by the subscriber (20 in my run).

Limits and honest caveats

  • Not investment advice. The README's target returns, Sharpe ratios and allocations are design goals, not results from this code.
  • The sample prices are synthetic (tickers like KOREA_STOCK_0000 with generated paths), dated 2023. Do not read them as market history.
  • Bug found: running pytest in backend gives 0 passed and 6 errors on my run: fixtures client and db_session are not defined, and psycopg and pytz are not in requirements.txt.
  • The pinned versions in backend/requirements.txt (for example pandas 2.1.3) are old; I used current unpinned versions on Python 3.15.
  • GET /health returns 404 in this version, despite what an integration test expects.
  • The README states 'Architecture Complete, Implementation Ready'; treat the repository as a design plus a skeleton.
