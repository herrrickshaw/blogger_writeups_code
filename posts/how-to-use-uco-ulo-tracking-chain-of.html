This post runs the tests, starts the API on seeded mock data and reads the compliance endpoints.

Why it is useful

  • Aggregators, re-refiners, biodiesel and SAF feedstock buyers, and compliance teams get a working reference model of a UCO/ULO custody chain: generator, collection manifest, lot, processing batch, dispatch and shipment, each with the quality fields (TPC, FFA, water, PCB, chlorine) that regulators care about.
  • It replaces spreadsheet mass balances and ad-hoc fraud checks with eleven named integrity heuristics (suspiciously fresh UCO, generator over capacity, duplicate manifest, lapsed registration, mass balance, implausible yield, PCB hazard and more) and a tamper-evident ledger.
  • The used-oil EPR module encodes the HOWM 2023 amendment arithmetic (producer target ladder 5/10/20/20/40/40%, Y-2 basis, certificate weightage 1.0 re-refining vs 0.25 co-processing, purchase cap of liability + 10%) so a producer's shortfall is computed, not eyeballed. Every threshold is an editable default served at /api/compliance/parameters.
  • Evidence from the run: 22 tests passed; the API seeded six months of mock data on first start and reported 73.9 t UCO and 30.5 t ULO collected, 18 high-severity flags (all planted deliberately in the seed), a 91-entry ledger with intact hash chain, and one of two EPR producers short by 15.68 t of certificates.

What it is for

The backend (backend/app) is a FastAPI service over SQLite with routers for supply (generators, collectors, collections, lots, batches, dispatches, shipments), compliance (integrity, EPR, certificates, recycler supply, returns, ledger, GHG, parameters) and a dashboard summary. On first start it seeds mock data with deliberately planted anomalies so each check has something to show. The front end (frontend/, React + Vite + Tailwind) renders the same data; it was not run for this post.

It is a sister project to saf-monitoring-system and a reference implementation for how UCO (a HEFA/biodiesel feedstock) and ULO (a hazardous waste re-refined to base oil) could be tracked in India. The README links a hosted front-end-only demo and a narrated walkthrough.

Regulatory numbers in backend/app/calculations/constants.py are editable defaults, several marked VERIFY or PLACEHOLDER. This post and the tool are not legal or regulatory advice.

Who it is for

  • UCO and ULO aggregators, re-refiners and biofuel feedstock buyers designing a traceability system
  • Compliance and sustainability analysts who want to see India's used-oil EPR rules as code
  • Developers building a chain-of-custody app who want a small, tested FastAPI + SQLite starting point
Not for.
  • Filing anything with CPCB, an SPCB or FSSAI: this is not legal advice and the thresholds must be reconciled with the official notifications first
  • Certified GHG accounting: the savings figures are indicative RED-style defaults, not CORSIA or RED III certified values
  • Treating a flag as a finding: the integrity checks are prompts to investigate, and the ledger is tamper-evident on one node only

Install

  1. Clone the repository
    git clone https://github.com/herrrickshaw/uco-ulo-tracking.git
cd uco-ulo-tracking/backend
  2. Create a virtual environment and install the backend dependencies
    python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

Quick start: commands and what you should see

Run the test suite

pytest -q

22 passed in about 11 s, with StarletteDeprecationWarning lines about httpx and the test client (harmless; see limits).

Start the API (seeds mock data on first run)

uvicorn app.main:app --port 8000
# interactive docs: http://127.0.0.1:8000/docs

Application startup complete. The first request seeds 8 generators, 7 collectors/processors, 12 lots, 12 batches, 14 shipments and 2 EPR producers.

Read the dashboard and the integrity flags

curl -s http://127.0.0.1:8000/api/dashboard/summary
curl -s http://127.0.0.1:8000/api/compliance/integrity

A summary with collected tonnes by material and output tonnes by product, ledger status and flag counts; then a list of 18 flags with check, ref, detail and severity.

See every regulatory threshold the model uses

curl -s http://127.0.0.1:8000/api/compliance/parameters

A JSON of editable defaults: FSSAI_TPC_LIMIT_PCT 25, UCO_SUSPICIOUSLY_FRESH_TPC_PCT 8, EPR_PRODUCER_PCT ladder 2024 to 2029, WEIGHTAGE re_refining 1.0 and co_processing 0.25, PURCHASE_CAP_MARGIN_PCT 10, EC_INR_PER_TONNE null, among others.

Limits and honest caveats

  • Everything shown is seeded mock data with planted anomalies; no real generators, collectors or producers. The front end was not run for this post.
  • The test run printed 93 warnings, including StarletteDeprecationWarning that httpx with the Starlette test client is deprecated. Tests still pass, but a future Starlette or httpx release could break them.
  • Regulatory defaults are editable placeholders. The README itself flags: the >50 L/day RUCO record-keeping threshold is known only via a press notice; the EPR conversion factor is set per recycler by CPCB and the default is a placeholder; Environmental Compensation (INR/t) is not captured; GHG defaults are indicative, not certified.
  • Fraud heuristics (fresh-oil TPC floor of 8%, 60% recoverable fraction) are analytical choices, not regulation. A flag is a prompt to investigate.
  • SQLite and a single node: the ledger is tamper-evident, not tamper-proof. See the end of docs/PLATFORM_REVIEW.md for what is not built yet. Not legal advice.
