Why there is no growth table this week

The previous edition was measured this morning.

Edition 02 re-queried its eleven repositories from the GitHub API on 8 August 2026. This edition was compiled the same day. There is therefore no interval to measure across, and publishing a growth column would mean publishing a column of zeros dressed up as stability.

So Edition 03 is a discovery edition: it goes looking for what the tracker has been missing rather than re-measuring what it already holds. The velocity table returns in Edition 04, when there is a week between the two readings and the numbers will mean something.

What the tracker had missed

Sixty-eight candidates, ranked by stars per day since creation.

Ranking by total stars returns the same established projects every week. Ranking by stars per day since the repository was created normalises for age, which is what “coming up” actually means: a ten-day-old project pulling twelve hundred stars a day is a stronger signal than a two-month-old one sitting on forty thousand.

A second measurement, because stars were not enough

Stars say who bookmarked a project. Forks say who took a copy to work with.

Every edition so far has carried the same warning — a star is a bookmark, it measures attention and not adoption — and then ranked on stars anyway. This edition adds a check that costs one extra API field: the ratio of stars to forks. Bookmarking is cheap and can be bought. Forking means somebody wanted the code on their own account.

Across the twenty candidates examined, the median ratio is 9.8 stars per fork. Two entries sit far outside it, in opposite directions.

unicity-aos/aos-ce has 8,573 stars and 17 forks. That is 504 stars for every fork, against a median of 9.8, and it has nine watchers. It also has not been pushed to since 31 July, while almost everything else on the list was updated within a day or two of this query. A great many people bookmarked an “open agent operating system” and essentially nobody took a copy to run. This edition is not calling that fraudulent — there are innocent explanations, including a launch that drew a wave of curious attention to a project not yet usable. But it is exactly the pattern a star count alone would have ranked fifth, and on this evidence it should not be treated as adoption.
The opposite outlier is also informative. ai-trader-bot has 1.4 stars per fork and 962 watchers — more people copying and monitoring than admiring. That is the signature of a template people fork to run rather than a library they depend on, which for an arbitrage bot connected to a smart contract is what you would expect. Nothing here evaluates whether it works or whether it is safe to run; the ratio only says how people are using the repository, not whether they should.

What is actually being built

Harnesses, inference tricks, and agents given ordinary office jobs.

The agent harness is the busiest category. qm, aos-ce, AgentENV, loop-engineering, omnigent and T3MP3ST are all infrastructure for running agents rather than agents themselves — scheduling them, giving them environments, keeping them in a loop. Edition 02 noted that plumbing was outgrowing products. Two weeks later the plumbing is most of the new arrivals.

Squeezing large models onto small machines is the second cluster. kimi-k3-in-c runs a 2.78-trillion-parameter model on one CPU in 8.24 GB with no framework and no GPU; turbo-fieldfare puts Gemma 4 26B on a MacBook in about 2 GB; waste streams weights beyond available RAM. Three separate projects, all inside a month, all attacking the same constraint.

And agents are being pointed at ordinary work. A CRM built for agents rather than salespeople, an AI-native office suite, a voice runtime. Whether any of it is used is a different question from whether it is starred, which is the point of Exhibit 2.

Method, and what it still cannot tell you

Written down so the next edition is comparable.

  • Discovery: eleven GitHub search queries, deduplicated by repository, filtered to repositories created within sixty days carrying at least 1,000 stars. Run by tools/ai_radar.py, so it is repeatable and the queries are inspectable.
  • Ranking: stars per day since creation, not total stars.
  • Quality check: stars per fork, against the median of the examined set.
  • Baseline for Edition 04: every figure here carries the exact query date of 8 August 2026, so next week’s growth rates will be exact rather than approximate.
What none of this establishes. Whether any project is used in production, whether it works, or whether it is safe. Stars can be bought and forks can be automated. Creation date is not launch date — a project developed privately and opened with an audience already waiting will show an inflated stars-per-day, and this edition cannot distinguish that from organic growth. GitHub search ranks what it indexes, so absence from this list is not evidence that something does not exist. And no model releases are covered this edition: they are not checkable against an API, and Edition 02’s unverified list is not repeated here rather than being carried forward unchecked.
