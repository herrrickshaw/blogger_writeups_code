Why it is useful

  • Hobbyists and indie creators who want to animate a still illustration get an honest map of the open-source options, with the dependency traps the author hit written down so you do not repeat them.
  • It replaces trial and error with paid closed tools: the README records which open-source route worked (Stable Video Diffusion on a public hosted Space) and which did not finish (ToonCrafter on Colab).
  • The one part you can run anywhere is original/render_lantern_oracle.py, which needs only Pillow, NumPy and ffmpeg and draws the artwork itself, so there is no model download and no copyright question.
  • Evidence from the run: the script finished in about 19 seconds and produced a 6.00 s, 144-frame, 720x960 H.264 MP4 of about 0.97 MB, matching the file committed in assets/.

What it is for

manga2anime tracks experiments in animating a static manga-style panel. The README documents two hosted image-to-video routes, and original/svd_run.py is a thin client for a public Stable Video Diffusion Space. original/render_lantern_oracle.py is separate: a fully procedural renderer for an original Art Nouveau, tarot-style panel that loops seamlessly.

This post runs the procedural renderer, because it is the only part that works offline and without a GPU. The hosted-model parts are described from the README and were not run here (see limits).

Who it is for

  • Creators comparing open-source image-to-video options before paying for a closed tool
  • Python learners who want a worked example of supersampled Pillow drawing turned into video with ffmpeg
  • Anyone who needs a short looping animation without a GPU or model download
Not for.
  • Animating copyrighted manga or anime: the repo's own source art is a public-domain stock illustration, and you are responsible for rights to any panel you use
  • Production-quality animation: the hosted models give short, loosely controlled clips
  • A one-command install: ToonCrafter needs a GPU and pinned old dependencies

Install

  1. Clone the repository.
    git clone https://github.com/herrrickshaw/manga2anime.git
cd manga2anime
  2. Create a virtual environment and install the two libraries.
    python3 -m venv .venv
.venv/bin/pip install pillow numpy
  3. Check ffmpeg is available.
    ffmpeg -version | head -1

Quick start: commands and what you should see

Render the original looping panel.

.venv/bin/python original/render_lantern_oracle.py

It prints a 'wrote ...' line naming assets/lantern_oracle.mp4 and assets/lantern_oracle_poster.png after roughly 20 seconds. Note that it overwrites those two committed files in your clone.

Inspect the result.

ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,duration -of default=nw=1 assets/lantern_oracle.mp4

h264, 720 wide, 960 high, 24 frames per second, 6 seconds.

Limits and honest caveats

  • Only the procedural renderer was run for this post. The SVD and ToonCrafter routes are described from the README and were not re-run.
  • The README says ToonCrafter was inconclusive: the Space hit its anonymous GPU quota, and the Colab fallback needed pinned 2023-era packages with no wheels for current Python.
  • The renderer overwrites assets/lantern_oracle.mp4 and the poster in your clone, so work in a copy if you want to keep the originals.
  • The artwork is the repo's original design; no manga or anime panels are reproduced here, and none should be assumed free to animate without checking their licence.
  • This is a hobby research repo, not a packaged tool: no tests, no versioned releases.
