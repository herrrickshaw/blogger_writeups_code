What it is for

Long jobs stop when Claude returns a rate-limit (429) or overload (529) error. Some data should never leave your computer. This repo gives you two small tools for those cases.

router.py is a one-shot command. It tries the Claude API first, retries twice on 429 or 529, and then sends the same prompt to a model served by LM Studio on your machine. Each call is written to router_log.jsonl, so you can see which engine answered.

claude_code_proxy.py is a local translator. Claude Code speaks the Anthropic API and LM Studio speaks the OpenAI API. The proxy converts between them, so the whole Claude Code agent can run on a local model, fully offline.

Who it is for

  • People who hit Claude rate limits on long batch jobs and want a draft answer anyway
  • Users who must keep some text on their own computer
  • Engineers who want to see how an Anthropic-to-OpenAI proxy works
Not for.
  • Getting Claude-quality answers from a local model. Treat fallback output as a draft
  • Image or vision work through the proxy. Image blocks are dropped
  • Anyone who expects the tools to start LM Studio for them. Neither tool does

Install

  1. Clone the repo and create a virtual environment.
    git clone https://github.com/herrrickshaw/claude-lmstudio-router.git
cd claude-lmstudio-router
python3 -m venv .venv
source .venv/bin/activate
  2. Install the packages. The repo has no requirements file, so install them by name.
    pip install anthropic
pip install fastapi uvicorn httpx   # proxy only
  3. Set your API key (skip if you will only use --force-local). Never put the key inside router.py.
    export ANTHROPIC_API_KEY="your-key-here"
  4. In LM Studio, load a model and click Start Server on the Developer tab.

Quick start: commands and what you should see

See the options.

python -I router.py --help

A usage line and options such as --prompt, --task, --input, --system, --output, --force-local, --force-claude, --local-base-url and --local-model.

Run with no key and no LM Studio, to see an honest failure.

python -I router.py --prompt "Summarize: tariffs"

It tries Claude and reports that ANTHROPIC_API_KEY is not set, tries LM Studio and reports that it could not reach http://localhost:1234, then prints FAILED: Both Claude and local LM Studio failed. router_log.jsonl records engine=none, success=false.

See the fallback path against a stand-in server. In the demo, port 1239 was a small canned server, not LM Studio.

python -I router.py --prompt "Summarize: tariffs" --local-base-url http://127.0.0.1:1239/v1

Claude is skipped because there is no key, then the output says Answered by: LOCAL with a canned reply. The log line shows engine=local, success=true and the reason for the fallback. With real LM Studio running, the reply would come from your loaded model.

Start the proxy, then check it. The demo used port 8792 through PROXY_PORT. The default is 8787.

python claude_code_proxy.py
curl http://127.0.0.1:8787/health

The health reply showed the proxy ok, LM Studio ok and the list of loaded models. With LM Studio really off, the proxy returned HTTP 503 and lmstudio: unreachable.

Run Claude Code through the proxy.

export ANTHROPIC_BASE_URL="http://127.0.0.1:8787"
export ANTHROPIC_API_KEY="local"
claude

Not run in the demo. In the demo a Read tool request was translated to OpenAI format for the backend, and the reply came back to Claude Code as an Anthropic tool_use block with stop_reason tool_use.

Limits and honest caveats

  • Local models are weaker and slower than Claude. Treat fallback output as a draft and consider re-running it through Claude later.
  • Claude Code needs a tool-calling model. Reasoning-only models often fail to emit tool calls.
  • Image blocks are dropped, so there is no vision through the proxy.
  • Neither tool starts LM Studio for you. You load the model and click Start Server.
  • With router.py, text goes to Anthropic whenever Claude answers. Only the fallback and the proxy path stay fully local.
  • No unit tests ship with the repo.
  • The demo used a canned stand-in server, not LM Studio. Live model calls were not run, so latency, answer quality and real tool-use loops were not measured.
  • The default model name (claude-sonnet-4-6) is set inside router.py. Check that it is still available to your account.
  • Pointing ANTHROPIC_BASE_URL at the proxy changes where Claude Code sends all its requests. Unset it to go back to the cloud.
