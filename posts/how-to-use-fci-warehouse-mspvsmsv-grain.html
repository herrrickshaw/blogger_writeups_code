Why it is useful

  • Agricultural-policy analysts, journalists and students asking 'does MSP actually hold in the market?' get a ready table of mandi modal prices against MSP, crop by crop, with sources recorded in a manifest.
  • It replaces stitching together CACP, Agmarknet, DFPD bulletins and FCI data by hand. The data/ folder holds 49 CSVs, and data/MANIFEST.md says where each came from and what is missing.
  • Evidence from the run: the mandi table shows 92% of bajra and 84% of moong market reports below MSP on 23 July 2026, against 19% for wheat. Two models also ran unchanged in a fresh environment.
  • The holding-economics model produced a clear result: for every commodity tested, estimated storage and financing cost exceeded price appreciation over 12, 24 and 36 months, which bears directly on the 'why not buy and hold' question behind MSV.

What it is for

FCI-warehouse-MSPvsMSV evaluates whether a Minimum Support Volume guarantee could extend effective price support beyond rice and wheat. It contains cited reports (report/), CSV data with a provenance manifest (data/), a self-contained HTML dashboard (dashboard/), a Colab notebook, and several Python models: holding economics, OMSS grain-processing unit economics, rice-bran oil savings, and a real farm income index.

This post uses the MSP series, the mandi-vs-MSP table and the two models that ran cleanly.

Who it is for

  • Agricultural-economics students and researchers
  • Journalists covering procurement, MSP and food stocks
  • Policy teams comparing price-support designs
  • Developers wanting a worked, sourced Indian agri dataset
Not for.
  • Investment or trading advice: this is not investment advice
  • Official statistics: figures are compiled from published sources and not audited
  • Farm-level decisions: models are stylised unit economics, not forecasts

  1. Clone the repository
    git clone https://github.com/herrrickshaw/FCI-warehouse-MSPvsMSV.git
cd FCI-warehouse-MSPvsMSV
  2. Create an environment and install dependencies
    python3 -m venv .venv && source .venv/bin/activate
pip install pandas numpy

Quick start: commands and what you should see

View the MSP vs mandi table

cat data/mandi_vs_msp_20260723.csv

16 crops with MSP, number of market reports, median modal price, share of reports below MSP and median gap.

Run the grain-processing unit-economics model

cd data && python3 omss_processing_model.py

EBITDA per quintal for wheat-to-atta and paddy-to-rice, plus a 300 TPD flour-mill scale case.

Run the holding-economics model

cd data && python3 holding_economics.py

Summary, horizon-return and post-crash-episode tables per commodity; it rewrites three CSVs next to the script, so run it in a copy if you want the repo untouched.

Limits and honest caveats

  • Not investment advice. Figures are compiled from public sources and unaudited.
  • Year labels differ between files. In msp_series.csv the year is the sowing year, so the rabi wheat MSP of Rs 2,425 sits under 2024-25 and Rs 2,585 under 2025-26, whereas mandi_vs_msp_20260723.csv uses the marketing-year MSP (wheat Rs 2,425 for 2025-26). Check the label before joining the two.
  • The mandi comparison is one day (23 July 2026) and includes crops with very few reports.
  • The holding-economics verdict depends on assumed carry rates (storage tariffs and financing) and WPI price series; it is not a forecast. Running it rewrites its three output CSVs.
  • The repo includes some company financials taken from screener.in; I did not use or reproduce them, and you should check licensing before reusing that file.
  • I did not run the other models (biodiesel, RBO savings, farm income index) or the dashboard, and the mandi data's upstream collection was not re-run.
