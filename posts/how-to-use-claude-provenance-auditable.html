Why it is useful

  • Who benefits: people who use Claude Code or claude.ai heavily and need to answer when, with which model, in which folder and on which git branch something was asked or done.
  • What it replaces: grepping scattered JSONL transcripts by hand.
  • Evidence from the run: a synthetic session of four messages became a queryable table with role, model, tool names, content length and a hash; a second run skipped the unchanged file.
  • Audit value: each row stores the source file and line number plus a SHA-256 of the full content, so you can recompute the hash later and detect edits.
  • Privacy note built in: the database holds transcript content, so it is meant to stay local and gitignored.

What it is for

claude-provenance reads transcripts that Claude Code already writes under ~/.claude/projects, your prompt history file, and optionally a claude.ai data export, and writes one SQLite file, provenance.db.

Each message row records where it came from (file and line), when (original and ingest timestamps), who (role, model, CLI version, git branch, working folder), what (record type, tool calls, a 300-character preview) and integrity and lineage (SHA-256, message id and parent id).

Re-runs are incremental: unchanged source files are skipped. --summary also writes a markdown summary of counts by source, project and model.

Who it is for

  • Teams or individuals who need a record of AI-assisted work
  • Researchers measuring their own AI usage
  • Anyone debugging which session changed something
Not for.
  • Sharing or publishing: the database and summary can contain echoed credentials and private text. Never commit them
  • Proving authorship to a third party: the hash detects edits to your local files, it is not a signature from Anthropic
  • Claude chats that exist only on the server and were never exported

Install

  1. Clone the repo
    git clone https://github.com/herrrickshaw/claude-provenance.git
cd claude-provenance
  2. Make sure provenance.db and PROVENANCE_SUMMARY.md stay out of git (the repo gitignores them in the author's setup; add your own ignore if you copy the script elsewhere)
    printf 'provenance.db\nPROVENANCE_SUMMARY.md\n' >> .gitignore

Quick start: commands and what you should see

Ingest everything and write the summary

python3 provenance_log.py --summary

'Parsed N files (...). Ingested M messages this run.' then the database path and the summary path.

Run it again

python3 provenance_log.py

'Parsed 0 files (N unchanged, skipped)': only new or changed transcripts are re-read.

Look at one day or one tool

sqlite3 provenance.db "SELECT ts, role, model, content_preview FROM messages WHERE ts LIKE '2026-10-01%' ORDER BY ts"

The messages of that day in time order.

Include a claude.ai export

python3 provenance_log.py --claude-ai-export /path/to/unzipped-export

Adds source claude-ai-export rows, one per chat message.

Limits and honest caveats

  • The demo used synthetic transcripts. On a real machine the database can be very large and can contain secrets that appeared in tool output; keep it private.
  • Observed in the run: the sessions table counted the tool-result message as a user message (n_user = 3 for a session with one typed prompt), so n_user over-counts human prompts.
  • It records only what exists locally. Server-side claude.ai chats need an export; deleted transcripts cannot be recovered.
  • The SHA-256 detects changes to your own copy; it does not prove the text came from Claude.
