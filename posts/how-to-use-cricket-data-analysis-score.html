Why it is useful

  • Who benefits: sports-analytics hobbyists and students who want a first, honest worked example of turning open match data into a ranking.
  • What it replaces: hand-copying results from scorecards. The script downloads the full public dataset in one step.
  • The idea is clean: score = 1 minus binary entropy of the dominant side's win share, so 0 means a coin flip and 1 means one side always wins.
  • Evidence from our run: the Cricsheet download succeeded (6.5 MB), but cricketdata 0.3.0 then failed to parse it. A workaround using the same formula gave a real ranking (below).
  • Caution: tiny samples dominate the top of the list (5 meetings can score 1.000), so read the sample sizes next to every score.

What it is for

Cricsheet publishes every match as CSV. This script downloads the IPL and ICC men's World Cup archives, normalises franchise renames (for example Delhi Daredevils to Delhi Capitals), keeps decisive matches, and computes a predictability score per team pairing and per venue.

It was extracted from stray copies in two stock-market repos, so it is a single standalone script rather than a package. It is an analysis exercise, not a betting or forecasting tool.

Who it is for

  • Students learning entropy as a measure of predictability
  • R users who want a worked example of the cricketdata package
  • Anyone curious which IPL match-ups have been lopsided
Not for.
  • Betting or match-outcome prediction. Past head-to-head records are not a forecast.
  • Quoting scores for pairings with few meetings as if they were stable
  • Anyone who needs it to run unchanged today: it currently stops with an error (see limits)

cd cricket-data-analysis
  2. Install the R packages
    Rscript -e 'install.packages(c("cricketdata","dplyr","tidyr","stringr","readr","lubridate","ggplot2"))'

Quick start: commands and what you should see

Run the script

Rscript fetch_and_analyze_cricket_data.R

It prints 'Fetching IPL match data from Cricsheet...', downloads about 6.5 MB, then should write five CSV files to ./output/. On our run (19 Oct 2026, cricketdata 0.3.0, tidyr 1.3.2) it stopped at the parsing step with the error shown below, so no CSVs were written.

Rscript fetch_and_analyze_cricket_data.R

Error in `tidyr::pivot_wider()`:
! Names must be unique.
x These names are duplicated:
  * "match_id" at locations 1 and 10.
Execution halted

Cause we found: the current Cricsheet *_info.csv files include an 'info,match_id' row, which collides with the match_id column that cricketdata 0.3.0 adds when it reshapes the data. This looks like an upstream package issue, not a bug in the repo script's own logic.

Workaround: the same score formula applied directly to the downloaded zip (our own small script, not part of the repo)

python3 -I pred.py   # reads *_info.csv from ipl_male_csv2.zip
decisive matches 1218 seasons 2007/08 - 2026
pairings with >=3 meetings 73

Pune Warriors vs Royal Challengers Bengaluru n= 5 dominant=Royal Challengers Bengaluru 5/5 (100.0%) score=1.000
Gujarat Titans vs Sunrisers Hyderabad        n= 7 dominant=Gujarat Titans 6/7 (85.7%) score=0.408
Mumbai Indians vs Pune Warriors              n= 6 dominant=Mumbai Indians 5/6 (83.3%) score=0.350

Top rows only. It applies the script's own rename map and the score = 1 - H(p) formula with a minimum of 3 meetings. The top scores come from teams that existed for only a few seasons.

Limits and honest caveats

  • The script does not run end to end today: cricketdata 0.3.0 fails on current Cricsheet files (duplicate match_id). We did not patch the repo.
  • Only the IPL download was exercised; the World Cup (ODI and T20) and venue-fortress outputs were not produced.
  • The workaround numbers are our re-computation of the same formula on 19 Oct 2026 data, not output of the repo script. Cricsheet updates continuously, so counts will change.
  • Head-to-head win share ignores toss, venue, squad and form, and the min-3-meetings filter still leaves very noisy scores.
  • Cricsheet data is shared under its own licence terms (see README.txt and LICENSE.txt inside the zip); check them before redistributing.
