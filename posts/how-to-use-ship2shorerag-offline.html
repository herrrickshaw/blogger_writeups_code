What it is for

ship2shore_rag is a search tool for maritime knowledge. It collects open sources (arXiv papers, Wikipedia, UK MAIB and US NTSB accident reports, plus any PDF or Word file you add), splits them into passages, and finds the passages that best match a question. Every result names its source, so you can check it.

It runs in two ways. On shore it uses Postgres with the pgvector add-on. On a vessel it uses one SQLite file, with no server and no internet. Both use the same search method: meaning-based search combined with keyword search, then a reranking step. Writing a final answer with Claude is optional. Without a key, the tool simply shows you the ranked passages.

The repository also has an operations module (vessel, crew, logbook, maintenance, fuel and incident records). This post covers the search side only.

Who it is for

  • Ship officers and superintendents who want to look up past incidents and definitions offline
  • Researchers and students studying maritime accidents, freight and regulation
  • Engineers who want a working example of offline hybrid search (RAG) with citations
Not for.
  • Replacing statutory logs or official records (the README says so)
  • Multi-vessel fleet software, or syncing a ship with the shore office (not built)
  • Legal, safety-critical or class decisions. Check the cited source every time

Install

  1. Clone the repo and create a virtual environment.
    git clone https://github.com/herrrickshaw/ship2shore_rag.git
cd ship2shore_rag
python3 -m venv .venv
source .venv/bin/activate
  2. Install the dependencies. This is the full list in requirements.txt, so it takes a few minutes.
    pip install -r requirements.txt
  3. Copy the settings file. For offline use, edit .env so it contains the two lines shown.
    cp .env.example .env
# in .env set:
# STORAGE_BACKEND=sqlite
# SQLITE_PATH=snapshots/ship2shore.sqlite3
  4. Optional, shore side only: install Postgres and pgvector, then create the schema. Skip this if you only want to search the snapshot.
    brew install postgresql@17 pgvector
# start Postgres on port 5433 and run createdb as in the README, then:
python3 cli.py init-db

Quick start: commands and what you should see

Ask a question and get ranked passages only (no API key).

python3 cli.py ask "What are the main causes of engine room fires on cargo ships?" --no-generate

A numbered Sources list, each with a title, URL and a short excerpt. In the demo the top hits were NTSB and arXiv items about an engine failure and an engine room fire, plus a Wikipedia page on container ships. The demo author noted these were only loosely related, because the corpus is small.

Ask a definition question and limit the number of results.

python3 cli.py ask "What is a bill of lading and what does it do?" --no-generate --top-k 3

Three passages. The first two came from the Wikipedia article on the bill of lading and the third from the article on charterparties.

Build a hazard brief for a job.

python3 cli.py hazard-brief "Hot work welding in engine room near fuel oil tanks" --top-k 3

A list of similar past incidents and guidance, each with a link. In the demo it returned an NTSB engine failure report and the Dali bridge contact report. It is retrieval only, not a risk score.

Measure retrieval quality on the 17 test questions in eval/queries.yaml.

python3 cli.py eval

Two summary lines. Rerank off: recall@5 = 0.76 and MRR = 0.706. Rerank on: recall@5 = 0.82 and MRR = 0.824. Questions that found nothing are listed as MISS.

Ways to use it

MethodHow it works
Command linepython3 cli.py ask, hazard-brief, eval, ingest and export-sqlite. This is the main interface.
Your own documentspython3 cli.py ingest --source file --path "./docs/**/*" adds PDF, text, Markdown, HTML, Word, Excel and PowerPoint files. Files stay on your machine.
Shore to vesselIngest on shore with Postgres, run python3 cli.py export-sqlite, copy the single file aboard, and set STORAGE_BACKEND=sqlite.
Reportsask --export briefing.html (or .txt) writes a small report you can attach to an email.
Web page and APIpython3 cli.py serve starts a small read-only web app on 127.0.0.1:8020. The repo also has a REST API (api.py) for the operations records.
Through an AI assistantOpen the cloned folder in Claude Code or Gemini CLI and ask it to run the commands above and explain the results.

Sample prompts for your AI assistant

Copy, paste and edit the parts in [brackets].

  • Read README.md and ARCHITECTURE.md in this repo and explain in plain English how a question becomes a list of cited passages.
  • Set this repo up to run offline from snapshots/ship2shore.sqlite3 and run one question with --no-generate. Tell me each command before you run it.
  • I have a folder of [my PDF reports]. Show me how to ingest them with --source file and then ask a question about [topic].
  • Run cli.py eval and explain recall@5 and MRR to me as if I had never seen them. Which questions missed, and why might they have?
  • Add three questions about [my topic] to eval/queries.yaml with the source I expect each to find, then re-run the eval.
  • What would break if I put this on a ship with no internet? List what needs to be downloaded first.

Limits and honest caveats

  • The corpus is small. In the demo, questions about engine room fires and hot work returned only loosely related reports.
  • The eval has 17 queries, so treat 0.76 and 0.82 as indicative, not as a benchmark. Three questions still missed with reranking on, including man overboard on a bulk carrier and the growth of maritime trade in 2023.
  • The committed snapshot holds 125 documents. The demo used a local file with 131 documents, so your counts and results will differ slightly.
  • It is not multi-vessel fleet software, and nothing syncs a vessel with the shore office (README).
  • It is not a replacement for statutory logs (README).
  • The web API still allows requests from any origin (CORS is open to all, README). Keep it on localhost.
  • Without an API key, ask only returns passages. Generated answers were not tested in the demo. Check any generated answer against the cited sources.
  • The demo ran every command with --no-generate and with models loaded from the local cache in offline mode.
