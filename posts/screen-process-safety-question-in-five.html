An LPG storage and loading terminal is a good test of any screening toolkit: pressurised propane bullets, transfer pumps, a road-tanker loading bay, a flare, and a control room and village close enough to matter. This post walks that asset through a free Python toolkit, step by step, with the actual outputs. The questions are the ones a process-safety workshop asks first: how big is the fire relief load, is the overfill trip good enough, where does the risk come from, and which fix is worth paying for.

The terminal here is hypothetical. It is the toolkit's worked example: four sections (a propane bullet with pumps, a road-tanker loading bay, a sour fuel-gas header, a diesel tank in a bund), 60,000 kg of propane at 750 kPag and 303 K in the bullet. Pump failure frequencies, weather, wind rose, population, building vulnerability, the value of a prevented fatality and mitigation costs are illustrative placeholders. The toolkit is a screen, not a safety case; replace every placeholder with site data before any decision.

1. Get it running

git clone https://github.com/herrrickshaw/process-safety-design-toolkit
cd process-safety-design-toolkit
git checkout feature/ifluids-service-map   # until the two open pull requests merge
python3 -m unittest discover tests         # 173 tests should pass
python3 -m process_safety coverage         # every topic, its standards, and what is NOT implemented

Start with coverage and read the “not implemented” lines. For an LPG terminal the ones that matter are layout and separation distances, hazardous-area classification extents, and a dense-gas dispersion model.

2. Walk the asset through the toolkit

How much vapour must the bullet relieve in a pool fire?relief-fire --D 3.5 --L 14 --level 2.5 --latent 330Wetted area 119 m², heat input 2,174 kW, relief rate 23,720 kg/h. The geometry and the 330 kJ/kg latent heat are inputs.

Which barriers carry the risk?tool bowtie bowtie.jsonTop event 1.7e-4 per year. Given a loss of containment: 69% unignited, 21% vapour-cloud explosion or flash fire, 9% jet fire, 1% BLEVE. The independent high-high level trip is the safety-critical element.

Is the societal risk acceptable?same runIndividual risk is tolerable if ALARP at all four receptors, but the F-N curve is in the intolerable region against the UK R2P2 preset.
How exposed are the buildings?same runOccupant risk per year: control room 5.0e-4, admin building 9.7e-5, loading-bay shelter 6.1e-3.
How far must emergency planning reach?same runCredible case (4-inch line rupture, jet and pool fire): 58, 102 and 179 m to 37.5, 12.5 and 4 kW/m². Worst case (bullet fireball): 296, 551 and 996 m. Vapour-cloud explosion: 621 m to 0.3 bar, 786 m to 0.1 bar.
Which fix pays?same runLoading-hose emergency release coupling with breakaway: prevents 0.046 fatalities per year at a cost-benefit ratio of 0.033, so implement. Extra shutdown valves on the fuel-gas header and relocating the admin building are not justified on cost-benefit alone.

Two readings are worth pausing on. The overfill function passes on probability and fails on architecture, so the fix is a redundant or higher-integrity final element, not a shorter proof-test interval. And the mitigation table says the cheapest, least glamorous measure at the loading bay removes most of the population risk. Both come from checks the toolkit runs, not from judgement added afterwards.

The limit that matters most for propane. The toolkit warns on this very study: propane is heavier than air, and the flash-fire and toxic footprints use a neutral Gaussian plume, so consider a dense-gas override. Dense clouds spread along the ground and reach further than a neutral plume. The vapour-cloud and flash-fire distances above (0.3 bar at 621 m, 0.1 bar at 786 m) and the risk that depends on them should therefore be treated as optimistic until footprints from a validated dense-gas tool such as DNV Phast or RISKCURVES are fed in through the overrides hook. The toolkit then still does the frequency, individual-risk, ALARP and mitigation bookkeeping.

3. Run the study the sensible way

python3 -m process_safety qra example --out study.json     # copy the worked terminal example
python3 -m process_safety qra validate study.json          # units, sums to 1, references, data provenance
python3 -m process_safety qra hazid study.json --out hazid/   # registers for the HAZID/HAZOP workshop
python3 -m process_safety qra run study.json --sample 3 --out sample/
python3 -m process_safety qra run study.json --out qra_out/

Run the --sample first: three scenarios on a coarser grid, a convergence check at double the angular resolution, and a projected run time. The full run of this 18-scenario terminal took 12.7 seconds. It writes the HAZID and HAZOP registers, an individual-risk grid, an F-N curve, building and emergency-zone reports, a mitigation table and an HTML report. Open qra_report.html first.

Why sample first. Building the study exposed two real bugs: a small leak inside a bund was given the whole bund area, and a village receptor was missed because plumes went down sector centrelines only. Both were caught by checks the sample run performs.

6. What this terminal needs next, and what would close each gap

  • Replace the placeholders. Pump and equipment frequencies from a source such as the OGP 434-1 data or the UK HSE FRED rows, local weather and wind data, and the actual population around the site.
  • Add a dense-gas footprint. Run the propane releases in a validated tool and feed the footprints through overrides.
  • Choose the criteria deliberately. This run used the UK R2P2 preset; no single Indian tolerable-risk criterion exists in the public documents the toolkit read, so an Indian site should supply a custom one.
  • Do what the toolkit lists as not implemented. Layout and separation distances, hazardous-area classification extents, and fire-water design to the governing standards remain manual work.
  • Hold the workshop. The HAZID and HAZOP registers are a starting point; the studies are a team exercise.

The same flow applies to other oil and gas assets, a gas processing plant, a refinery unit or an offshore platform, with different modules in play (relief and flare systems, hydrocarbon fire, explosion). The terminal here is only the asset the toolkit ships a worked example for.
