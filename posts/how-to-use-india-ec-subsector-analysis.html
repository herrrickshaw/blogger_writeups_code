Why it is useful

  • Policy researchers, consultants and journalists can see in one table which states dominate each industrial activity's environmental clearances, something the government's own dashboards do not pivot.
  • It replaces a scraping campaign: the register was captured once and is committed as a 2,055-row CSV plus two JSON files, so analysis needs only Python's standard library.
  • Grant rates differ sharply by activity (Construction 80.6%, Mining 69.9%, Townships 37.8%, River valley 21.5%), pointing to where clearances actually stall.
  • Evidence from the run: row counts summed to 113,970 and the 5(f) state table was built in a few lines; the Gujarat share (56.2%) matches the README.

What it is for

The repo turns the PARIVESH 2.0 Environmental Clearance register into a state by sub-sector matrix. Each proposal's sub-sector is its EIA-schedule activity code (for example 5(f) Synthetic organic chemicals). Status is bucketed into granted, ToR-granted, in-process, dead and delisted, and a grant rate is computed excluding delisted proposals.

It also compares EC filings with industrial investment intentions (IEMs) and covers forest, wildlife and CRZ clearances, which this post does not run.

Who it is for

  • Researchers and students studying industrial and environmental regulation in India
  • Consultants sizing where clearance activity concentrates, by state and by sector
  • Journalists and civil-society analysts who want a reproducible pivot, not screenshots
Not for.
  • Deciding the status of a specific project: the data is a snapshot as of the fetch date, not live
  • Year-on-year trends: the README says it is a pipeline snapshot, not a time series
  • Legal advice or any regulatory filing. Not legal advice.

Install

  1. Clone the repository
    git clone https://github.com/herrrickshaw/india-ec-subsector-analysis.git
cd india-ec-subsector-analysis
  2. No install is needed for the committed data. To refresh later (optional, large download):
    python3 scripts/refresh_ec.py

Quick start: commands and what you should see

Check the committed CSV and the snapshot date

python3 -I -c "import csv,json;r=list(csv.DictReader(open('data/ec_state_subsector.csv')));print(len(r),sum(int(x['count']) for x in r));print(json.load(open('data/ec_subsector_analysis.json'))['built'])"

2055 113970 followed by the snapshot date 2026-07-22.

Build a state-wise table for one sub-sector (here 5(f))

python3 -I state_table.py 5\(f\)   # 12-line script: filter the CSV on activity_code, sum by state and status

A table of the top states with granted, ToR-granted, in-process, dead and delisted counts and a grant rate (see sample output).

  • Write a short method note that explains the limits of this snapshot for a policy brief.

Limits and honest caveats

  • Ran on the committed snapshot built 2026-07-22; the live PARIVESH register has moved on. The refresh script (about 126 MB download) was not run.
  • The data is a snapshot as of fetch date, not a time series. 8,037 proposals have no parseable activity code and are excluded from the sub-sector view.
  • Grant rate excludes delisted proposals (roughly 22% of the register), so it reflects live decisions only.
  • Small states show extreme rates on few proposals (Uttarakhand 90.0% on 63).
  • The IEM versus EC comparison, the forest, wildlife and CRZ analysis and the GitHub Pages site were read from the README only, not run.
  • The state_table.py helper shown is a short script written for this post, not part of the repo.
  • Public government data only. Not legal advice.
