Why it is useful

  • Who benefits: trade, tax and compliance researchers, legal-data builders and journalists who must trace a notification through its amendment chain.
  • What it replaces: manually hunting for 'in the notification number X, dated Y' references across separate PDFs on egazette.gov.in.
  • Evidence from the run: the seed SQL files rebuilt a database of 2,637 notifications and 2,150 cross-references across 53 ministries, with an empty foreign-key check.
  • Evidence from the run: the repo's own test suite passed (197 tests, 0.3 seconds) and one Customs notification (45/2025) showed 9 incoming links, including 2 corrigenda.

What it is for

Gazette Trail is a citation index. Each notification is a row; each 'amends', 'supersedes', 'corrigendum', 'rescinds', 'repeals' or 'cites' link is a row in a cross_reference table. Reading the links in both directions gives you the lineage of a rule: what it changed and what changed it later.

The links are drawn from real quoted notification text, recurring sentence shapes are matched by shared regex templates, and each ministry module has its own tests. The pilot is CBIC customs notifications, extended to 53 central ministries.

This demo used only the committed SQL seed files and ran no live fetch. Nothing was downloaded from egazette.gov.in, and no PDFs or OCR were used.

Who it is for

  • Researchers and compliance teams tracing amendments to Indian rules
  • Developers building legal or regulatory knowledge graphs
  • Data journalists who need an amendment chain for a notification
Not for.
  • Legal advice. This is an index of public notifications, not a legal opinion; read the official notification before acting.
  • A complete or up-to-date record. Coverage is bounded and the repo says new notifications must be checked with its freshness script.
  • Reading the full legal text. The database stores citations and summaries, not the PDFs.

Quick start: commands and what you should see

Build the database from the seed files.

sqlite3 gazette.db < db/schema.sql
for f in db/seed_*.sql; do sqlite3 gazette.db < "$f"; done
sqlite3 gazette.db "PRAGMA foreign_key_check;"

The foreign-key check prints nothing, which is the pass condition.

Run the test suite.

pytest tests/

In the 19 October 2026 run: 197 passed in 0.30s (the README still says 141 tests, so its counts lag).

Read one notification's lineage.

python3 -c "
import sqlite3
from db.crud import get_lineage
c=sqlite3.connect('gazette.db'); c.execute('PRAGMA foreign_keys = ON')
print(get_lineage(c,'power-so-5852-2022'))"

A dictionary with 'points_at' and 'pointed_at_by'; here one later power-ministry notification amends it.

Limits and honest caveats

  • Citation index of public notifications, not legal advice. Verify against the official egazette.gov.in notification.
  • README counts lag the data: it says 2,591 notifications, 2,113 cross-references and 141 tests; the 19 October 2026 build gave 2,637, 2,150 and 197.
  • Coverage is bounded: 53 ministries are modelled, 3 are documented as abandoned, and new notifications need the freshness check.
  • The demo did not fetch any PDFs, run OCR or translation, and did not use the optional Colab notebooks (not run).
  • The built-in page renderer (render.pages) was not run in this demo.
