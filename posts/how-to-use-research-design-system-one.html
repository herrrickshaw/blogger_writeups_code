Why it is useful

  • Who benefits: analysts and writers who publish reports, newsletters and dashboards and want a consistent look with almost no CSS work.
  • What it replaces: re-copying styles between HTML pages, Blogger themes and one-off dashboards.
  • Evidence from the run: the same report template rendered in all four themes by changing only the theme stylesheet and one body class; a screenshot of each was captured.
  • Rules baked in: units in table headers, a source note on every exhibit, reading width capped at 68 characters, wide tables scrolling in their own container.
  • Documents three real bugs it prevents: invisible text in dark mode, drop-caps from Blogger themes, and WeasyPrint print hangs.

What it is for

research-design-system consolidates design assets found across about 42 repos and two Blogger properties into tokens/tokens.css, four theme files, components/components.css and print/print.css.

The contract is that components only use semantic tokens (--c-text, --c-accent and so on). A theme just rebinds roughly a dozen of those tokens, so a new theme is a short file.

Templates for a report, a bulletin and a dashboard, a live component gallery in docs/index.html and an INVENTORY.md of the original assets are included.

Who it is for

  • Analysts publishing HTML reports or bulletins
  • Developers building a simple dashboard shell
  • Anyone standardising a house style across several pages
Not for.
  • Pixel-exact brand work: it is a small starter kit, not a corporate brand system
  • Pages that need JavaScript widgets: only CSS is provided
  • Dark mode that follows the OS: dark mode is opt-in by design (data-theme="dark") and only theme-reportage models it fully

Quick start: commands and what you should see

Start from a template and open it

cp templates/report.html my-report.html   # then fix the ../ paths or keep the file inside the repo
open my-report.html

A report page with masthead, in-brief card, stat tiles, a table exhibit, a side box and a warning box. The stylesheet links must be in this order: tokens, theme, components, print.

Switch theme

sed -i '' 's#themes/report.css#themes/slate.css#; s#theme-report#theme-slate#' my-report.html

The same content on a dark slate ground with blue accents. Use theme-bulletin, theme-report, theme-reportage or theme-slate.

Make your own theme

cp themes/report.css themes/mine.css   # then rebind the --c-* tokens

Components pick up your colours because they never reference raw palette values.

Ways to use it

MethodHow it works
Copy a templateStart from templates/report.html, bulletin.html or dashboard.html and replace the text.
Link the CSSLoad tokens, theme, components and print in that order, then add class="rds theme-<name>" to body.
Print to PDFprint/print.css sets A4 page rules for WeasyPrint; follow the README's warnings about page-total spans and flex containers.
Via an AI assistantAsk Claude Code or Gemini CLI to turn your notes into a page using the report template and theme-reportage.

Limits and honest caveats

  • Conceptual starter kit, not a finished brand or engineering design.
  • The numbers inside the shipped templates (for example trade totals in the sample table) are placeholder example content, not data to cite.
  • Only the visual render of the four themes was run; the WeasyPrint PDF path and the Blogger theme in blogger-theme/ were not tested for this post.
  • A scratch copy of the report template was edited per theme for the screenshots; the repo itself was not modified.
  • Dark mode is opt-in; the page will not follow the operating system unless you add data-theme="dark" yourself, which is deliberate.
