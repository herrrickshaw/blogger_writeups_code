Why it is useful

  • Who benefits: independent quant researchers and students who want ready-made scanners, a lookahead-free backtest engine and cost-aware screen testing in one codebase.
  • What it replaces: stitching together separate scanners, cost models and factor notebooks; the repo has about 50 modules, documented in one README table.
  • Evidence from the run: the repo's unit tests ran offline in a fresh virtual environment and passed (119 tests in 14 seconds).
  • Evidence from the run: DuckDB queried the committed net-of-cost screen results directly, showing that only 8 of 25 market-screen pairs stayed positive after costs at the 21-day horizon.

What it is for

BazaarTalks bundles several things: full-universe scanners for five regions (Darvas, Piotroski, Coffee-Can) that write Excel workbooks; a point-in-time US backtest using SEC EDGAR filing dates; screen testing net of transaction costs; factor research (quality, post-earnings drift, liquidity); and a Durability, Valuation and Momentum scoring layer across many markets.

Results live in a DuckDB warehouse over Parquet files, with an optional Cassandra cache and Kafka streaming path, and a read-only FastAPI service plus an SVG dashboard.

This demo kept to what runs cheaply and offline: the unit tests and DuckDB queries over the committed result tables. I did not run the scanners (they call market-data APIs), the Cassandra and Kafka backbone, or the dashboard, which needs a built warehouse that is not in the repo.

The repo also contains code for logging in to paid data services with your own account. Those sessions are not used here, and the data they fetch should not be redistributed.

Who it is for

  • Quant students and independent researchers who want a transparent, testable codebase
  • Developers who want a template for a Parquet plus DuckDB research warehouse
  • Readers who want cost-aware, point-in-time method notes (PIT_BACKTEST_RESULTS.md, NET_OF_COST.md)
Not for.
  • Investment advice or trading signals. Not investment advice.
  • A one-command install: it lists heavy and optional dependencies (Cassandra, Kafka, Flink, Playwright)
  • Redistributing vendor data fetched through the optional paid-account sessions

Quick start: commands and what you should see

Run the offline unit tests.

pytest -q

In the 19 October 2026 run: 119 passed in about 14 seconds, no network or Cassandra needed.

Query the net-of-cost screen results with DuckDB.

python3 -c "import duckdb; duckdb.sql(\"select market, count(*) screens, sum((net_viable='YES')::int) viable, round(avg(net_edge),2) avg_net_edge from 'net_viability_21d.csv' group by 1 order by 4 desc\").show()"

A five-row table by market (see sample outputs).

Run a scanner (needs network).

python full_indian_market_scan.py --top 200

Not run in this demo; it writes a styled Excel workbook.

Limits and honest caveats

  • Not investment advice. Research code; results are historical and net of assumed, not real, costs.
  • Scanners, the live pipeline, Cassandra, Kafka, the dashboard and serve.py were not run (need network, services or a built warehouse). Only unit tests and DuckDB queries over committed CSVs ran, on 19 October 2026.
  • The repo's .db files are 8 KB empty stubs and cache_seed_local/cleaned_long_IN.parquet is a Git LFS pointer, so the warehouse must be built locally.
  • PIT_BACKTEST_RESULTS.md notes survivorship bias and uneven sample months; its Coffee-Can arm fired in only 19 of 56 months.
  • The README title and Colab link say global-market-scanners, so names differ from the repo name.
  • requirements.txt is long and pins heavy optional packages; install only what you need.
