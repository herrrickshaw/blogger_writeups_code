A small Python command-line tool that reads a portfolio file and prints buy, hold or sell labels, a three-month gain figure per stock and a holding-cost view based on the Newsvendor idea from inventory theory. This post runs it on an invented portfolio and shows how the rules actually behave. Not investment advice. The repository is archived (read-only).

Why it is useful

  • Who benefits: students and curious investors who want to see how a transparent rule set turns holdings into labels, and how the Newsvendor holding-cost versus regret-cost idea is applied to shares.
  • What it replaces: a spreadsheet of ad-hoc rules. The whole scoring logic is a few hundred lines of readable Python.
  • Evidence from the run: on six invented holdings it produced a summary, a top-gainers list and hold or sell lists in under a second, and I could trace every label to a rule.
  • It also shows why such labels deserve scepticism: they depend on the sector table and the buckets, not on any market data. Details in the limits below.

What it is for

The package loads a portfolio from a generic CSV or Excel file (symbol, quantity, purchase price, current price, optional sector) or from a particular broker tax report. A StockEvaluator scores each holding from its return so far, a fixed sector and beta table, and a Newsvendor holding-cost calculation. Three commands print the results: evaluate, gainers and actions.

It is an educational rule-based tool. It is not investment advice. The three-month gain figure is a formula of fixed sector numbers, not a forecast, and the tool fetches no prices or news. The repository is archived.

Who it is for

  • Students learning how a Newsvendor model can be mapped to holdings
  • Individual investors who want to see what a simple rule set says about their own file, as a thought experiment
  • Non-programmers who want an AI assistant to explain each rule
Not for.
  • Making buy, hold or sell decisions. Not investment advice.
  • Treating the three-month gain figure as a prediction. It comes from a fixed table.
  • Uploading anyone's real account reports to a chat tool without checking what they contain.

Install

  1. Get the code (the repository is archived, so you can clone it but not push)
    git clone https://github.com/herrrickshaw/stock-portfolio-evaluator.git
cd stock-portfolio-evaluator
  2. Create an environment and install
    python3 -m venv .venv && source .venv/bin/activate
pip install -e .
  3. Make a small test file with invented numbers
    printf 'symbol,quantity,purchase_price,current_price\nTCS,10,3000,3300\nZOMBIECO,50,200,120\n' > demo.csv

Quick start: commands and what you should see

Run the tests, from the tests folder (running pytest from the repo root fails, see limits)

python -m pytest -q tests

6 passed.

Print the full report

stock-eval evaluate demo.csv --report

A summary, top gainers, hold or buy list, sell list and recommendation distribution.

Show only the top gainers

stock-eval gainers demo.csv --top 3

Ranked list with sector, gain figure and current return.

Show hold and sell lists

stock-eval actions demo.csv

Two lists with the recommendation label per stock.

Limits and honest caveats

  • Not investment advice. The labels come from fixed rules, not from fundamentals, prices, news or any forecast.
  • The 'three-month gain potential' is a sum of fixed numbers: a base, a momentum bucket on past return, a sector value and a beta term. It does not look at the market.
  • The rules favour past losers and mark past winners as SELL, so a 40% loss earns STRONG_BUY in my run.
  • Sectors come from a small hard-coded table matched by substring, and unknown symbols default to Technology. Holding period is fixed at 365 days.
  • An empty sector cell prints as nan and skips the lookup (the sector then has no beta or gain entry).
  • Running pytest from the repository root fails because an old duplicate copy of the package sits in a subfolder; run it inside the tests folder.
  • The README refers to a DOCUMENTATION.md that is not in the repository, and the one example script only works with a broker report path you must edit.
  • The tool also parses a broker's tax report; this post used only invented data and no real account files.
