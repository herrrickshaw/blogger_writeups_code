What it is for

A battery pack needs software to track how full it is (state of charge) and how worn it is (state of health), because neither can be measured directly. The software must also balance cells, limit power, manage temperature and cut the contactor on a fault.

This library puts those pieces in one package: a two-RC Thevenin cell model, an Extended Kalman Filter for charge level, a wear model, passive cell balancing, thermal control, power limits and a supervisor with fault codes. It is for simulation and learning.

Who it is for

  • Engineers and students learning how a battery management system works
  • EV and e-mobility analysts who want a runnable reference
  • Non-programmers who want an AI assistant to explain each part
Not for.
  • Running a real battery pack. This is a simulation, not firmware.
  • Predicting the life of a specific real cell. The ageing model is a simple linear fade.
  • Treating the validation numbers as real-world accuracy. They come from synthetic data.

Install

  1. Get the code
    git clone https://github.com/herrrickshaw/bms-battery-management.git
cd bms-battery-management
  2. Create an environment
    python3 -m venv .venv && source .venv/bin/activate
  3. Install the listed requirements (numpy, pytest) plus the two packages the README leaves out
    pip install -r requirements.txt pandas matplotlib

Quick start: commands and what you should see

Compare the vehicle classes

python -m bms.simulation

A comparison table: 2-wheeler LFP 15S1P 48 V, 4W retrofit lead-acid 36S1P 72 V, 4W modern LFP 32S1P 102 V, bus LFP 128S2P 409 V (163.8 kWh), with the algorithms and chemistries supported. The plot run (--plot) did not finish within two minutes in the demo.

Simulate a 2-wheeler charge and discharge (use 2W, not two_wheeler)

python -m bms.simulation --vehicle 2W

A time table of state, charge percent, pack voltage, current, hottest cell and fan speed. Charging started at 15.0% and reached 56.8% at 52.2 V and 47.1 C. After discharge: SOC 53.4%, no fault, SOH 99.99%.

Run the 300-cycle degradation model

python -m bms.simulation --degradation

Health falls 0.1% per cycle: 95.0% at cycle 50, 80.0% at cycle 200, 70.0% at cycle 300, with resistance rising from 2.00 to 2.60 mOhm. WARNING status from cycle 225. End of life at 80% is about cycle 200.

Validate against dataset-shaped data

python -m bms.simulation --datasets

On synthetic data: charge-estimate RMSE 0.117% (target below 3%, PASS), voltage-model RMSE 1.07 mV (target below 20 mV, PASS), remaining-life RMSE 4.2 cycles, and one degraded module found out of several.

Run the test suite

pytest tests/

112 passed in 10.33s.

Limits and honest caveats

  • The validation numbers come from synthetic data matching Kaggle dataset layouts. Real Kaggle files are optional and downloaded separately.
  • The degradation model is a simple accelerated linear fade, not a measured cell model.
  • README gaps found in the demo: requirements.txt lists only numpy and pytest, but --datasets also needs pandas and the plot needs matplotlib.
  • The README example uses --vehicle two_wheeler, but the CLI accepts 2W, 4W_RETRO or BUS.
  • The all-vehicle plot run did not finish within two minutes in the demo, so no plot is shown.
  • This is simulation code, not battery firmware, and it has not been validated on a physical pack.
