What it is for

This repository is a learning reference. It shows how an ICU aggregation dashboard can be put together: fetch bedside-monitor numbers, check them against alarm rules, stream them to a screen, and keep a single patient record that other features write into.

It uses open, de-identified surgical cases from VitalDB. The patient names, health ID numbers, insurer and policies are all invented. Nothing connects to a real hospital, a real health ID system or a real insurer.

Who it is for

  • Engineers who want to see a live-vitals pipeline (replay, alarm rules, WebSocket, React) in one small codebase
  • Health-IT students and researchers learning how a linked patient record is structured
  • Non-programmers who want to ask an AI assistant how an ICU dashboard works
Not for.
  • Any clinical use, patient care or monitoring of real people. It is not a medical device.
  • Real health ID or insurance integration. Both are simulated.
  • Production hosting. It runs as one process with a SQLite file.

Install

  1. Get the code
    git clone https://github.com/herrrickshaw/patient-history-tracking.git
cd patient-history-tracking
  2. Optional: install Tesseract if you want the OCR features
    brew install tesseract
  3. Create the backend environment and install dependencies (fastapi, uvicorn, vitaldb, numpy, websockets, pytesseract, Pillow, python-multipart)
    cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
  4. Start the backend
    uvicorn app.main:app --port 8710
  5. In a second terminal, start the dashboard, then open http://localhost:5273
    cd frontend
npm install
npm run dev -- --port 5273

Quick start: commands and what you should see

List the beds (the demo called the API in-process; with the server running, request the same path on port 8710)

GET /api/beds

Seven beds, Bed-A to Bed-F plus Bed-DEMO, each backed by a VitalDB case (for example Bed-A is case 4096). Bed-DEMO has a 40-second encounter and is marked demo=True.

Watch the live vitals stream

WebSocket /ws/vitals

One tick per bed with heart rate, oxygen saturation, respiratory rate and systolic blood pressure. At sim_t=8, Bed-A showed HR 76, SpO2 100, RR 19. Some values are None when a case has no reading.

Look up a bed's synthetic health ID

GET /api/beds/Bed-A/identity

A generated name, a synthetic ABHA-style number, age 53, sex F, General surgery, Cholecystectomy, plus a disclaimer that the number is not real.

Check simulated insurance and prescriptions

GET /api/beds/Bed-DEMO/insurance
GET /api/beds/Bed-DEMO/prescriptions

An invented insurer, an eligible status, and an approved claim (CLM-0585570804). Six illustrative orders that show as discontinued after the demo bed's discharge.

Read the append-only record timeline

GET /api/beds/Bed-DEMO/record

Admission, eligibility check, prescriptions, alerts, discharge, discharge summary and claim in one timeline, 27 events in total.

Get the discharge summary

GET /api/beds/Bed-DEMO/discharge-summary

Vitals ranges (for example HR 71 to 82, SpO2 99 to 100), one alert (RR low), the approved claim, and a disclaimer that it is not a real clinical document.

Limits and honest caveats

  • DEMO DATA, NOT FOR CLINICAL USE. This is a prototype, not validated, and not a medical device.
  • Alarm thresholds are illustrative defaults and have not been clinically reviewed.
  • The health ID, insurer, policies, claims and prescriptions are invented. No real ABDM or insurer integration exists.
  • Storage is a single SQLite file in one process, so it does not scale across machines.
  • The OCR features (local Tesseract) were not exercised in the demo. The README reports handwriting OCR misread 650mg as 850mg, so every extracted result goes to a human review queue.
  • VitalDB data is licensed CC BY-NC-SA 4.0 under a data use agreement: non-commercial, and no re-identification. Cite Lee et al., Scientific Data 2022 if you build on it.
  • The demo called the API in-process rather than through a running server, so the browser dashboard itself was not shown in the numbers above.
