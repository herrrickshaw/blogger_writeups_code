Why it is useful

  • Students, consultants and developers who need to understand how EU carbon-market obligations (ETS surrender, CBAM declarations, shipping MRV) connect get a working, inspectable system instead of PDFs.
  • It replaces a diagram-only explanation with an API you can call: declare imports, see default-value mark-ups applied, reconcile a quarter and watch certificates net off.
  • Evidence from the run: after seeding in a fresh clone, I declared three default-value consignments and one with supplied actuals over the API and reconciled Q1 2026; the numbers matched hand calculation from the default-value table.
  • The run shows why the choice matters in CBAM: for the same 1,000 t of Indian steel, default values gave 3,223 t of embedded CO2 versus 2,200 t with supplied actuals (illustrative data).

What it is for

This is a prototype that models modules after real reference systems: EU Union Registry for ETS accounts and surrender, EMSA THETIS-MRV for shipping, the CBAM Transitional Registry for importers, and the Climate Action Data Trust for credit sourcing. An India CCTS module adds sector targets, Article 6.2 activities and carbon-price comparisons.

Every tenant's private data is isolated, while market data such as order books and credit projects is shared across tenants, as on a real marketplace.

Who it is for

  • Developers and students learning how carbon-compliance systems are structured
  • Analysts who want to experiment with CBAM default-value versus actual-emissions effects
  • Teams prototyping multi-tenant compliance software
Not for.
  • Real EU ETS, CBAM, MRV or CCTS filings: this is not legal advice and not a certified compliance tool
  • Any use of the seeded numbers as real prices, emission factors or allocations
  • Anything relying on the India module as primary-source law; the repo says it comes from secondary reporting

Install

  1. Clone and enter the backend
    git clone https://github.com/herrrickshaw/eu-ets-compliance-platform.git
cd eu-ets-compliance-platform/backend
  2. Create a Python 3.11 virtual environment and install pinned dependencies
    python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

Quick start: commands and what you should see

Seed the illustrative data (drops and recreates the local SQLite tables)

python -m app.seed.seed_data

'Seed complete.' followed by a table of 13 demo tenants and their login emails, with the demo password printed.

Start the API

uvicorn app.main:app --port 8000

Interactive API docs at http://127.0.0.1:8000/docs. Log in via POST /api/auth/login with a printed demo account, then use the bearer token.

Declare a CBAM import and reconcile a quarter (shown in sample outputs)

POST /api/cbam/imports
POST /api/cbam/declarations/{declarant_id}/{year}/{quarter}/reconcile

Emissions computed from default values with mark-up, or from actuals if supplied.

Limits and honest caveats

  • Not legal advice and not a certified compliance tool. The README says all data is illustrative and must not be used for real filings.
  • I ran the backend only (seed plus API calls through a test client). The React front end and the trading, credit and verification flows were not run.
  • There is no automated test suite in the repo; the checks shown are my own API calls on 19 Oct 2026 against a freshly seeded database.
  • The reconcile step adds direct and indirect emissions for every good. Real CBAM treats indirect emissions differently by product; check the regulation before relying on totals.
  • Default-value factors and the CBAM phase-in schedule are seeded illustrative values, not official figures.
  • The India CCTS module comes from secondary reporting, not gazette text or an official API, per the repo's own source notes.
  • The README states the demo password openly; this is a local demo only, so never deploy it as is.
